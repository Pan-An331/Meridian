# Task OS · UI ↔ API 数据流全景

> 审查人：UI Designer · 日期：2026-08-02 03:28
> 方法：全量 grep 前端 fetch 调用（21 个调用点）+ 逐个 route.ts 出入参审计
> 架构：**页面层（UI）→ fetch → API 路由 → Prisma/服务层**；components 层零 fetch（页面即容器）

---

## 一、分层总览

```
┌─────────────────────────────────────────────┐
│  UI 页面层（6 个页面 + 认证）                  │
│  login / register / today / inbox / plan /   │
│  review / settings（+ week 重定向到 plan）     │
└──────────────┬──────────────────────────────┘
               │ fetch（JSON）
┌──────────────▼──────────────────────────────┐
│  API 层（20 个接口被 UI 实际使用 / 46 个路由）  │
│  全部要求登录（getServerSession，401 拦截）     │
└──────────────┬──────────────────────────────┘
               │ Prisma / AI 服务 / 规则引擎
┌──────────────▼──────────────────────────────┐
│  数据层：SQLite(dev.db) · AgentMemory · AI API │
└─────────────────────────────────────────────┘
```

- **输出（显示）**：页面挂载时 GET 拉取 → 渲染区块
- **输入（操作）**：用户操作 → POST/PUT/DELETE → 响应后刷新（reload）
- 所有写操作后统一 `load()` 刷新页面数据，无乐观更新

## 二、按页面：输入 / 输出全景

### 1. Today 页（执行驾驶舱）— `/today`

**输出（数据 → 区块）**

| 区块 | 来源 API | 响应字段 |
|---|---|---|
| 头部问候 + 统计 | GET `/api/views/today` | todayStats.{completedCount,totalMinutes} |
| Focus Card（圆环计时/清单/学习） | 同上 | currentTask{id,title,description,parentTitle,children[],scheduledStart,scheduledEnd,elapsedMinutes,plannedMinutes,completionPercent} |
| 多卡切换（←→ 圆点） | 同上 | currentTask + mustDo[]（无当前任务时取 mustDo[0]） |
| 状态仪表盘 | 同上 | currentState{energy,focus,mood,stress} |
| 今日路线 | 同上 | todayTimeline[]{taskId,title,start,end,duration,isCurrent} |
| AI 调整助手建议 | 同上 | recommended[]{taskId,title,reasons} |
| 布局模式（一栏/两栏） | localStorage | taskos.fcLayout（不进 API） |

**输入（操作 → API）**

| 操作 | API | Body |
|---|---|---|
| 完成 / 跳过 | POST `/api/tasks/{id}/action` | {action:"complete"\|"reschedule", reason} |
| 子任务勾选 | POST `/api/tasks/{childId}/action` | {action:"complete"} |
| 保存备注 | PUT `/api/tasks/{id}` | {description} |
| 状态调整保存 | POST `/api/user-state` | {energy,focus,mood,stress} |
| AI 建议采纳 | POST `/api/plan/apply-decision` | {changes:[{taskId,newStart,newEnd}]} |
| AI 对话输入 | POST `/api/agent/chat` | {input} |

### 2. Inbox 页（AI 理解入口）— `/inbox`

**输出**

| 区块 | 来源 API | 响应字段 |
|---|---|---|
| 空输入画布 | 无（纯前端） | — |
| AI 整理结果卡 | POST `/api/inbox/analyze` | data：解析后的 draft items（复杂卡阶段展开 / 简单卡） |
| 最近处理列表 | 前端 state（confirm 后累积） | — |

**输入**

| 操作 | API | Body |
|---|---|---|
| AI 整理 | POST `/api/inbox/analyze` | {content} |
| 确认创建（单卡/全部） | POST `/api/inbox/confirm` | {draftId, confirmed[]} |
| 忽略（负反馈） | POST `/api/agent/feedback` | {agentAction:"inbox_analyze", userResponse:"rejected", agentSuggestion} |
| 卡片操作（编辑保存→创建） | POST `/api/tasks` | {title,description,taskType,category,importance,...} |
| 撤销 | POST `/api/tasks/{id}/action` | {action:"delete"} |

### 3. Plan 页（时间规划）— `/plan`

**输出**

| 区块 | 来源 API | 响应字段 |
|---|---|---|
| 高效时段条 | GET `/api/views/week-calendar` | peakHours[] |
| 本周截止卡（badge+展开子任务） | 同上 | allActiveTasks[]{id,title,deadline,source,children[]} |
| 周历甘特图（时段/任务块/角标） | 同上 | scheduledTasks[]{id,title,status,category,startTime,endTime,source,deadline} |
| 收集箱 | 同上 | plannedTasks[]{...,deadline,source,children} |
| 详情 Popover（三型卡） | GET `/api/tasks/{id}` | task{taskType,deadline,schedule,children,timeLogs} |

**输入**

| 操作 | API | Body |
|---|---|---|
| 收集箱点击排期 / 拖拽 | POST `/api/plan/apply-decision` | {changes:[{taskId,newStart,newEnd}]} |
| 调整时间 / 移除 | POST `/api/plan/apply-decision` / POST `/api/plan/delete` | {changes} / {taskId} |
| 详情面板开始/完成/子任务 | POST `/api/tasks/{id}/action` | {action:start\|complete\|delete} |
| 子任务勾选/追加 | POST `/api/tasks/{childId}/action` + POST `/api/tasks` | {action:"complete"} / {title,parentId} |
| 周历刷新 | GET `/api/views/week-calendar?weekStart=` | — |

## 五、数据流要点

1. **页面挂载即拉全量**：today/plan/review 各一次 GET 拉全部区块数据（无局部接口），操作后整页刷新
2. **写操作统一走 action 聚合**：任务状态机（start/pause/complete/snooze/postpone/reschedule/delete）全部收敛在 `/api/tasks/[id]/action`，入参按 action 取用（postponeDays/snoozeUntil/newStart 等）
3. **排期唯一入口**：`/api/plan/apply-decision`（changes 批量）—— Plan 拖拽、Today 采纳、收集箱排期三处复用；改时间不直接碰 schedule 表（遵循"Schedule 唯一时间源"规则）
4. **AI 反馈闭环**：inbox 忽略 → feedback(rejected)；review 应用建议 → memory(preference)；today 采纳 → apply-decision 写 feedback/decisionLog
5. **配置类全部 localStorage + 服务端双轨**：导航/版式走 localStorage；AI 配置/作息/资料走服务端
6. **未登录 401 统一拦截**：所有 API 服务端 getServerSession，UI 侧依赖 nextauth 重定向
