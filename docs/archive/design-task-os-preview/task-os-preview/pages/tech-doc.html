项目概述

核心理念

Task OS 是一个个人任务管理系统，核心理念是「帮助用户过滤未来，不是堆积未来」。它不是另一个待办列表，而是一个智能的决策辅助系统，帮你从繁杂的信息中提取真正重要的事。

四页面链

Inbox

收集一切输入，AI 解析并分类

Plan

制定计划，AI 辅助调度

Today

今日聚焦，AI 智能排序

Review

回顾反思，数据驱动优化

设计原则

1

AI 不是聊天机器人。AI 是系统的智能引擎，在后台默默工作，不需要用户对话。

2

用户最终控制权。所有 AI 建议都是可选的，用户始终拥有最终决定权。

3

零 AI 可用是底线。即使 AI 服务完全不可用，系统核心功能仍可正常运行。

用户综合行为模型。整合多维度模式，形成对用户工作习惯的完整画像。

AI 数据流

任务类型体系

inbox

未处理的原始任务，进入收集箱等待 AI 解析

planned

已规划但未排期的任务，在计划视图中管理

scheduled

已排入日程的具体任务，有明确时间窗口

Inbox 解析流

用户输入 → 文本预处理
AI 解析 → 提取标题、时间、优先级、类型
分类打标 → inbox / planned / scheduled
用户确认 → 正式入库，AI 建议可修改

AI 知识层四层架构

L1 UserObservation — 原始观察层

收集用户每次操作的原始数据：任务创建、时间安排、完成情况、修改行为等

L2 UserPattern — 模式挖掘层

从观察数据中提取规律：工作时段偏好、任务完成率、拖延模式、精力周期等

L3 AgentMemory — 记忆存储层

持久化重要上下文：用户偏好、历史决策、关键事件、学习到的经验

L4 UserModel — 综合模型层

多维度综合画像：工作风格、时间类型、精力曲线、项目偏好，驱动个性化 AI 决策

核心规则

不可违反的 4 条核心规则

规则 1：用户最终控制权

所有 AI 建议必须经过用户确认才能执行。AI 不得自动修改、删除、或创建任务。任何自动化操作都需要用户显式授权。

规则 2：数据不可丢失

任何操作不得导致用户数据丢失。删除操作必须软删除，保留恢复能力。关键操作记录到 DecisionLog。

规则 3：AI 透明可审计

所有 AI 决策必须记录在 DecisionLog 中，包含决策内容、理由、置信度。用户可以随时查看和质疑 AI 的建议。

规则 4：离线可用

AI 服务不可用时，系统核心功能（任务 CRUD、日程管理、查看回顾）必须正常运行。AI 功能优雅降级，不阻塞用户操作。

Memory 状态生命周期

状态 说明 转换条件
active 活跃记忆，当前正在使用中 创建时默认 / 重新激活
decaying 衰减中，重要性降低 7 天未匹配
archived 已归档，不再参与决策 30 天未匹配 / 用户手动归档
consolidated 已合并到 UserModel 模式置信度 >= 0.85

Agent Tool 权限等级

等级 权限 示例 Tool
READ 只读访问，可以查看数据 getTasks, getSchedule, getPatterns
SUGGEST 可以生成建议，需用户确认 suggestSchedule, suggestPriority
ANALYZE 可以分析数据，生成洞察 minePatterns, analyzeProductivity
EXECUTE 可以执行操作（需显式授权） createTask, updateSchedule（受限）

项目运行

环境要求

Node.js >= 20 npm >= 10 SQLite 3 OpenAI API Key (可选)

安装与启动

终端 
# 克隆项目
git clone https://github.com/your-org/task-os.git
cd task-os

# 安装依赖
npm install

# 配置环境变量
cp .env.example .env.local
# 编辑 .env.local 填入 API Key

# 初始化数据库
npx prisma db push
npx prisma generate

# 启动开发服务器
npm run dev
