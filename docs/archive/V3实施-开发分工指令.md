> 流程：**前端先出预览 UI（mock 数据）→ 用户验收 → 后端升级（数据库+API）→ 前端对接真实数据**

## 0. 工作流总览

```
┌─────────────────────────────────────────────────────────────┐
│ 第 1 步：前端工程师出「预览 UI」（mock 数据，不依赖后端）      │

                             ↓ 验收通过

                             ↓ 后端就绪

│ 第 3 步：前端工程师把 mock 换成真实 API（对接）               │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 设计约束（红线）

- **卡片三层规则**（D6）：任何卡片只显示 身份→时间→状态，其余进详情。禁止自创卡片样式
- 主题角标：竞赛红/考研橙与领域底色必须清晰可辨（对比度 ≥ 4.5:1）
- 文案统一：「计划状态」（inbox=想法/planned=截止日/scheduled=时间块），不再用「任务类型」

### 1.4 交付验收标准（给用户）

- [ ] 主题角标颜色一眼可辨，周历不糊
- [ ] 档案面板五层齐全、编辑跳转按钮清晰
- [ ] Inbox 表单"（含竞赛）"提示可见
- [ ] 卡片不超载（三层规则成立）
- [ ] 预览用 mock 数据跑通，不需要后端

### 1.5 预览验收后的实现提醒（正式项目落地必读，2026-08-02 审核结论）

> 预览稿 `UI示例/V3预览-信息架构实施.html` 已通过审核（含 3 处修复）。正式实现时注意：

1. **全局搜索索引必须实时构建**：正式实现用 `GET /api/tasks/search` 从 tasks 表实时查询（标题/标签/归属链 contains），**禁止硬编码 mock 索引**；搜索结果 id 必须是真实 taskId（预览稿曾出现两条结果共用 id 导致点开错位的 bug）
2. **档案面板主题 chips 要接真实交互**：预览已补点击切换；正式实现切换后保存走 `PUT /api/tasks/[id]`（theme 字段），并触发领域/主题修改反馈回流（AgentFeedback）
3. **Review 统计排除测试数据**：主题投入/关键词统计/指标卡必须排除测试任务（可约定测试账号或测试数据打标），否则统计失真（预览稿"测试拖动/测试inbox"已污染"其他"主题）
4. **本周截止区排除已完成任务**：已完成任务置灰弱化或移出截止列表（预览已对"提交报告"置灰删除线处理）
5. **主题推断边界（resolveTheme）**：拿不准就留空（AI 不强猜）；"学习PLC"这类容易被误判"考研"的标题，规则要保守（PLC 更可能归属课程/实践，仅当明确出现"考研"语义才判考研）
6. **主题徽章对比度 ≥4.5:1**：深色文字 + 浅底 + 色点方案保留（纯 #DB2777 白字仅 4.2:1 不合格，弃用）
7. **周历任务块加 0.5px 细边框**（rgba(15,23,42,.07)）：紫块在淡紫时段背景（晚上 #f5f3ff）上必须可辨
8. **时段背景用户钦定**：上午纯白 / 下午 #fef9e7 偏黄 / 晚上 #f5f3ff 淡紫（与旧代码上午黄/下午白相反，按此执行）

### 2.2 实施清单（按阶段 A→D 顺序，每阶段验证后再进下一阶段）

**阶段 A：数据库**
- [ ] A1. schema 变更：删 `temperature`/`startTime`/`endTime`/`cognitiveLoad`/`schedulingHint`；加 `theme String?` + `@@index([userId, theme])`
- [ ] A2. 迁移脚本（5 步）：competition→practice+theme:竞赛；考研关键词回填 theme；剥离 tags 系统前缀；校验无残留
- [ ] A3. `prisma migrate dev` + `prisma generate` 双跑

**阶段 B：服务层**
- [ ] B1. `src/lib/plan/colors.ts`：DOMAINS 移除 competition（7 类）；新增 THEMES 表（竞赛 #DB2777/考研 #F97316）；新增 `resolveTheme(tags,title,category?)`；TAG_MAP 移除"考研/英语"→learning；删 `buildTagsForDomain`
- [ ] B2. `src/lib/ai/parser.ts`：ParsedTask +theme；prompt 加主题判断（拿不准留空）；fallback 加主题关键词
- [ ] B3. `src/lib/ai/confirm-service.ts`：theme 落库；category 白名单 7 类；时间只走 Schedule
- [ ] B4. 新增 `src/lib/task/theme.ts`：getTheme / themeColor / normalizeThemeInput

**阶段 C：API**
- [ ] C1. **新增** `GET /api/tasks/search?q=`（标题/标签/归属链 contains，空 q 400）
- [ ] C2. `POST /api/tasks`：+theme；移除死字段；category 白名单
- [ ] C3. `PUT /api/tasks/[id]`：白名单 +theme
- [ ] C4. `POST /api/inbox/analyze`：items +theme
- [ ] C5. `GET /api/views/today`：currentTask +theme/themeColor
- [ ] C6. `GET /api/views/week-calendar`：scheduledTasks/plannedTasks +theme；图例 +themes
- [ ] C7. `GET /api/tasks/[id]`：档案面板聚合 +theme/+ancestors/+schedules/+accumStats/+aiFields(只读)
- [ ] C8. `GET /api/views/stats`：+themeBreakdown（主题时长/完成数/占比/周环比）+ `?theme=` 过滤 + 指标卡数据（周完成率/采纳率/堆积率/打卡保持率）

- [ ] D1. buildAgentContext 注入 theme 分布

## 3. 协作与交接

- **并行**：前端预览（第 1 步）与后端阶段 A-B（第 2 步）可并行；前端对接真实数据须等阶段 C 完成
- **契约对齐**：前端 mock 的字段名必须与 V3 §4.4 API 契约一致（theme/themeColor/ancestors/schedules/themeBreakdown），避免对接返工
- **交付报告**：每阶段完成写一段简报（改了什么/验证结果/遗留），更新 docs 决策记录
- **冲突处理**：SSOT 纪律——本文档/总控 V2.0/V3 与代码冲突时，改代码不改文档；确属产品决策变更 → 追加 V3 §7 决策记录
