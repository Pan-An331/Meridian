## 二、核心方案 · 时间性质三态（命名定稿：截止日 / 时间块 / 事项）

### 命名定稿（用户钦定）
```
有 Schedule      → 「时间块」（固定起止时间）
有 deadline      → 「截止日」（有明确结束点）
两者都没有      → 「事项」（一件要做的事，未安排时间）
```
- 「**事项**」取代「想法/待安排/已排期」——用户判定：状态词不像分类；「事项」是**任务性质**，能和「截止日/时间块」并列比较
- 显示仍是**动态推导**（deriveTimeState）：排期后标签自动变「时间块」，取消排期回「事项」——用户核心诉求（"排期后不该还叫想法"）不变，只是换成了性质词
- 全局替换 7 处「想法」标签 + taskType 降级为创建意图（阶段 2 评估退役）
- Inbox 类型入口改为**时间安排动作**：「加子任务 / 设每天 / 设有截止」+「拖到日历 = 自动时间块」

### 第二个维度：重要性（小事/大事）
- 「小事/大事」= importance（1-5，字段已有）——**与三态正交**（图见决策对话）
- 现状缺口：**importance 全站 UI 零暴露** → 用户没工具表达"小事"
- 方案：Inbox 确认表单加重要性三档（低/中/高）+ 档案面板可改 + 低价值任务弱化显示（配合"过滤未来"）
- → **⏳ 唯一待拍板项**：重要性三档是否随批次 2 一起做？
