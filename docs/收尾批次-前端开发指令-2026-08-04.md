## 阶段 A · 续排按钮「明天继续」（高频痛点，最有价值）

**现状**：后端完全就绪，前端零入口——
- `POST /api/tasks/[id]/action` body `{action:"continue_tomorrow"}` → 复制该任务最近一次排期的时段到明天（保留时长），返回 `{continued, nextStart}`
- `GET /api/plan/continuations` → 返回未完成任务的续排建议列表：`[{taskId, title, lastStart, lastEnd, suggestedStart, estimatedMinutes}]`（规则：昨天/今天有排期但未完成 + 明天还没有排期的任务，排除积累型）

**改动**（两个落点，A1 必做，A2 可选增强）：

**A1 · Plan 页续排建议条**（必做）
- 位置：Plan 页「收集箱」上方加一条「未完成任务 · 明天继续」折叠条（参考本周截止折叠条的交互：默认收起只露 badge「N 个续排」）
- 展开后每项：任务名 + 上次时段（如"昨天 09:00-11:00"）+ 建议明天时段 + 「复制到明天」按钮
- 点按钮 → `POST /api/tasks/[id]/action {action:"continue_tomorrow"}` → 成功后 toast「已排到明天 HH:00」+ 该项移出列表（或列表刷新）
- 空态：「没有需要续排的任务 🎉」灰字

**A2 · Today Focus Card「明天继续」次级按钮**（增强，可选）
- 位置：Focus Card 主按钮旁（未出发/进行中态），次级按钮「明天继续」（弱化样式，白色底 + 品牌色文字）
- 点击 → 同 A1 的 action → toast 提示

**验收**：Plan 页出现续排条 → 点「复制到明天」→ 刷新后该任务在周历明天出现同时间段块，续排条该项消失。

## 阶段 B · 忘记确认提示条（Focus Card 闭环最后一块）

**现状**：后端已返回 `views/today` 的 `currentTask.departureAt`（出发时刻），惰性结算只处理了"有排期到点自动完成"，但**"出发了没回来确认"的任务没有任何提示**——用户可能 7 小时前点了出发去干活，回来忘了确认，卡片还停在"进行中"。

**改动**（`src/components/today/FocusCardV2.tsx` 或 today/page.tsx 包一层）：
- 判断条件：`card.departureAt` 存在 && 任务未完成 && `now - departureAt > 阈值`
- 阈值建议 **4 小时**（产品文案按实际小时数显示："已出发 7 小时没确认"）
- 触发后卡片顶部（动机行下方）出现**警示条**：
  - 文案：`已出发 X 小时没回来确认 —— ① 做完了？[补记完成] ② 还在做，继续`
  - 「补记完成」→ 走现有 `onComplete`（补记时长弹窗，默认 = 现在 − departureAt）
  - 「还在做」→ 关闭提示条（session 级，不做持久化），保持进行中
- 样式：琥珀底（`#FFFBEB`）+ 金色左边条 + 13px，不抢主按钮视觉

**验收**：mock departureAt 为 5 小时前 → 提示条出现；点「补记完成」→ 补记弹窗默认值 = 5 小时；点「还在做」→ 提示条消失且不再弹。

## 阶段 C · Focus Card 左栏「项目阶段」直读项目树（去 mock）

**现状**：`FocusCardV2` 左栏 stages（阶段链）+ projectProgress（项目进度）的渲染位已存在（`stages?: {name, done?, current?}[]` / `projectProgress?: {done, total}`），但 today/page.tsx **没接真实数据**，一直是 mock/空。

**后端已就绪**：`GET /api/projects/tree` 返回完整树（每节点含 `id/title/level/status/doneCount/totalCount/parentId/children/star/themeColor`）。

**改动**（today/page.tsx，前端自算祖先链，零后端改动）：
1. 拿到 `currentTask.parentId` 后 → `fetch('/api/projects/tree')`（建议页面级 fetch 一次 + 缓存，不随卡片刷新重复请求）
2. 递归在树里找到 currentTask 所在链路的**祖先链**（从项目根 → 阶段 → … → 当前任务）
3. 组装：
   - `stages` = 祖先链各级 `{name: 节点title, done: status==='completed', current: 该级是当前任务所在的直接父级链}`（只有 level 为 project/phase 的节点入链）
   - `projectProgress` = 最近一个**有 doneCount/totalCount 的祖先**的完成度（树接口已聚合）
4. 找不到（孤儿任务）→ 保持 `stages` 为空（现有渲染位 `card.stages.length > 0` 已处理空态）

**验收**：真实挂树任务（如"画原理图"挂"四轴飞行器"下）→ 左栏显示「四轴飞行器 › 画原理图」阶段链 + 项目进度条；孤儿任务不显示。

## 阶段 D · 积累·每日卡 mini-cal 小日历（规格 §3.3 保留项）

**现状**：积累·每日卡（accum-daily）有三格统计（连续/最长/本月）和频次点阵，但**当月小日历缺失**（V1 有，V2 迁移时没带过来）。

**数据依赖**：后端 `accumStats` 即将新增 `monthDates: string[]`（当月打卡日期，YYYY-MM-DD 列表，见后端指令 A1）——**后端未就绪前先用 mock 数组占位，就绪后一行切换**。

**改动**（`FocusCardV2.tsx` 积累·每日卡）：
- 位置：三格统计下方（或频次点阵旁），加**当月小日历**：7 列网格显示当月 1-N 号（周一开头）
- 视觉：非打卡日灰点/空、打卡日**金色小圆点**（呼应金点打卡语义）、今天日期加品牌色描边、上月/下月日期置灰（灰字 30%）
- 数据：`card.accumStats.monthDates`（需在数据接口加字段）+ 当月天数
- 尺寸克制：不喧宾夺主，高度约 3 行网格（当月 31 天排 7 列 = 5 行，可压缩行距）

**验收**：积累每日卡显示当月小日历，打卡日金色高亮，今天有描边。
