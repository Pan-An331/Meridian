## 一、任务类型全景（四种）

| 类型 | 例子 | 模型落位 | Today 卡片 |
|------|------|---------|-----------|
| 固定时间型 | 上课 / 开会 | ★task 直接创建，无子级 | 计时型（现有） |
| 产出型·简单 | 采购 | ★task + 备注拆行清单（青菜/牛肉） | 清单型（备注行） |
| 产出型·复杂 | 4 轴飞行器 | 项目根 → 阶段… → ★task → 下一级清单 | 清单型（真实子级，分组） |
| **积累型（新）** | 背单词 / 健身 | ★task + `accumulate` 标记 + 打卡记录 | **打卡型（新）** |

### 积累型任务定义

- **没有产出物、没有"完成"**：核心是"坚持"——每天来一次，攒连续天数
- 创建：Inbox 一句话（"每天背单词 20 分钟"）→ AI 识别积累语义 → 自动生成**每日重复排期**
- 数据：任务本体（★task）+ `accumulate` 标记 + 打卡记录（每天一条）
- 展示：Today 打卡卡片 = 今日打卡按钮 + **连续天数** + 历史最长 + 近 30 天点阵
- 排期：每天同一时段自动重复（复用 schedule 多行，Plan 周历每天一块）
- 无完成联动（不触发 D2），不参与 Review 完成率（按打卡率统计）

## 四、改造方案

### Part A：标记字段

```prisma
level       String?  @default("task")  // project | phase | task
accumulate  Boolean  @default(false)   // 积累型标记（★task 的子标记）
```
- 均无损可空，`db push` 直接加
- 写入点：AI 解析 + Inbox 卡片可改 + 整理页点标 + tasks 白名单

### Part B：AI 解析建树 + 积累识别

- parser/types：breakdown 递归结构（≤4 层）；新增积累语义识别（"每天/坚持/背单词/健身/打卡" → accumulate + 周期）
- task-builder：递归建树；积累型任务生成每日重复排期（未来 30 天，可调）
- 规则降级：保持现有能力 + 关键词识别积累型（"每天/坚持"）
- Inbox 编辑表单：叶子平铺编辑 + 层级分组展示 + 积累开关

### Part C：Today 就近两级 + 积累卡片

**C1. 就近两级**（D5）
- 清单 = ★当前任务直接子级（group 标签）；归属 = 祖先链；兜底 = 备注拆行 / 任务自身
- 真实子级勾选写库；备注行勾选 localStorage

**C2. 积累卡片**（D9）
- 形态：打卡按钮 + 连续天数 + 最长记录 + 30 天点阵（见示意）
- 打卡 = 创建当天打卡记录（复用 timeLog，minutes 默认估计时长）；今天已打卡 → 按钮变"已打卡 ✓"
- 连续天数：按打卡记录日期去重，算当前连续段 + 历史最长段
- 30 天点阵：绿=打卡 / 空=漏卡 / 浅=未来

### Part D：完成联动（D2）

- complete 后兄弟全完成 → 父自动完成（递归，cancelled 不阻塞）；无反向联动；积累型不参与

### Part E：重复排期（D4 待定）

- 积累型：创建时自动生成每日重复排期（天然满足）
- 普通任务续排：方案 1「明天继续」按钮 / 方案 2 手动拖拽 / 方案 3 AI 建议

### Part F：项目整理页（D6/D7：树形大纲 ✅）

- `/projects` 页签；树形大纲编辑器
- 左侧树（展开/折叠/缩进）：标题 + 状态 + ★标记 + 积累标记
- 右侧待整理池：未挂树 active 任务 + 已完成任务（搜索）
- 拖拽池→树 / 树上→树上（改 parentId）；节点菜单：标 ★ / 积累开关 / 移除关系
- 循环防护：目标非自身子孙；归属校验（userId 铁律）
- 已完成任务拖入：parentId 挂树，状态不变（D8 用途待确认）

### Part G：积累型任务（D9）

**G1. 数据**：复用 timeLog 作打卡记录（不建新表）
- 打卡 = 一条当日 timeLog（startedAt=打卡时刻；补打可指定日期）
- 连续天数统计：timeLog 按日期去重 → 当前连续段 + 历史最长段（工具函数 `getStreak(userId, taskId)`）

**G2. 排期**：创建时自动生成每日重复排期（同一时段，未来 N 天）；Plan 周历每天一块

**G3. Today**：C2 打卡卡片；打卡后当天排期标记"已打卡"

**G4. 统计**：Review 打卡率（本月打卡天数/天数）；pattern-mining 可挖"坚持中断"模式（增强项，可选）

## 五、兼容性

- 存量任务 level 默认 task，accumulate 默认 false（无行为变化）
- 无数据迁移；schema 仅加两个可空字段
- 存量 Inbox 草稿格式兼容

## 六、边界与风险

| 边界 | 默认处理 |
|------|---------|
| 树过深 | 归属链上限 5 级截断；整理页不限 |
| 移动循环 | 校验目标非自身子孙 |
| 打卡补打 | 允许指定日期（防忘打），标记补卡 |
| 连续天数中断 | 点阵直观显示；不自动提醒（可后续加） |
| 积累型误识别 | Inbox 卡片可改（开关） |

## 七、明确不做

1. ❌ 不改 Review/Plan 展示逻辑（打卡率除外，见 G4）
2. ❌ 不做 reopen 反向联动
3. ❌ 不做任务模板/批量生成
4. ❌ 整理页不做排期（排期仍在 Plan）
5. ❌ 不做打卡提醒推送（后续独立功能）
