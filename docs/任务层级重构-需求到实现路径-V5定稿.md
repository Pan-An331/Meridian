## 一、需求全景（定稿）

### 1.1 层级模型：任意深度 + ★task 锚点

```
4 轴飞行器（项目根）
└─ 硬件设计（阶段）
   └─ 画原理图（★ task，用户指定）   ← 唯一锚点：能排期 / Today 当前任务
      ├─ 芯片模块（阶段）             ← ★ 直接下一级 = Today 执行清单
      └─ 驱动模块（阶段）
```

- 除项目根外所有层统一语义 = 阶段，深度不限
- **★task 由用户标记**（AI 推断 + Inbox 卡片可改 + 整理页点标）
- Today：★下一级 = 清单；★祖先链 = 归属；无子级有备注 → 备注拆行；都没有 → 任务自身
- 叶子全勾 → 父自动完成（递归向上，无反向联动）

### 1.2 四种任务类型

| 类型 | 例子 | 模型 | Today 卡片 |
|------|------|------|-----------|
| 固定时间型 | 上课/开会 | ★task | 计时型 |
| 产出型·简单 | 采购 | ★task + 备注拆行 | 清单型 |
| 产出型·复杂 | 4轴飞行器 | 树 + ★task | 清单型（分组） |
| 积累型 | 背单词/健身 | ★task + accumulate + 打卡 | 打卡型 |

### 1.3 积累型（D9）

- 无"完成"，只有"今日打卡"；连续天数自动算
- 创建时自动生成每日重复排期（默认 30 天，同时间段）
- 打卡复用 timeLog（不建新表）；补打可指定日期
- 不参与完成联动；Review 按打卡率统计

### 1.4 项目整理页（D6/D7/D8）

- 侧边栏「项目」页签，**树形大纲**编辑器
- 拖拽建树（池→树 / 树上→树上）；**已完成任务拖入 = 归档复盘**（状态不变，节点显示已完成勾选态）
- 节点菜单：标 ★ / 积累开关 / 移除关系
- 循环防护 + 归属校验

### 1.5 续排（D4：手动+自动联合）

- 手动：任务卡「明天继续」按钮（一键复制明日排期）+ Plan 页拖拽（已有）
- 自动：晚间 AI 建议"XX 未完成，排到明天？"一键确认

## 二、数据模型变更（唯一 schema 改动）

```prisma
model Task {
  // 新增两个字段（均可空/默认，db push 无损）
  level       String?  @default("task")   // project | phase | task
  accumulate  Boolean  @default(false)    // 积累型标记
}
```

- **不建新表**：打卡记录复用 `timeLog`（type 增加 `"checkin"`；统计按 startedAt 日期去重）
- 连续天数工具：`src/lib/task/streak.ts` → `getStreak(userId, taskId)` 返回 { current, longest, lastDate, todayChecked }

## 三、API 契约（UI 开发的接口来源）

### 3.1 修改的接口

| 接口 | 变更 |
|------|------|
| `POST /api/tasks` | body 增加 `level`、`accumulate`、`repeatDays?`；accumulate=true 时自动生成每日重复排期 |
| `PUT /api/tasks/[id]` | 白名单增加 `level`、`accumulate`（parentId 已在） |
| `POST /api/inbox/analyze` | 解析产物支持：多级树 + 每项 level + accumulate 识别 |
| `POST /api/inbox/confirm` | 多级事务建树 + 积累重复排期 |
| `POST /api/tasks/[id]/action` | 新增 action：`continue_tomorrow`（明天继续） |
| `GET /api/views/today` | 响应增加：归属链 ancestorChain、清单分组 group、积累卡片数据（streak/todayChecked） |
| `GET /api/views/week-calendar` | scheduledTasks 增加 `level`/`accumulate` 字段（渲染积累块/★标记） |

### 3.2 新增接口

| 接口 | 方法 | 用途 | 请求 | 响应 |
|------|------|------|------|------|
| `/api/projects/tree` | GET | 整理页读树 | - | `{ trees: [{ id, title, level, accumulate, status, completedAt, children: [...] }] }`（未挂树任务在 `orphans`） |
| `/api/projects/move` | POST | 移动节点 | `{ taskId, newParentId: string\|null, sortOrder? }` | `{ success }`（循环防护：newParentId 不能是 taskId 自身子孙；校验归属） |
| `/api/tasks/[id]/checkin` | POST | 打卡 | `{ minutes?, date? }` | `{ success, streak: { current, longest, todayChecked } }` |
| `/api/tasks/[id]/streak` | GET | 打卡统计 | - | `{ current, longest, lastDate, todayChecked, last30: string[] }`（30 天点阵数据） |

## 六、验证计划（每步完成即验）

1. `tsc --noEmit` + `vitest run` + `next build`
2. 手测 Inbox：「每天背单词 20 分钟」→ 积累卡片 + 30 天重复排期；「4轴飞行器：硬件设计（画原理图：芯片/LED）」→ 三层树
3. 手测 Today：★任务就近两级、归属链、备注兜底、打卡→连续天数→点阵、勾完清单→父完成
4. 手测整理页：拖拽（含已完成）、标 ★、积累开关、循环防护
5. 手测续排：明天继续 → 明日排期出现；AI 建议 → 确认后排期

## 七、风险与边界（定稿）

- 归属链上限 5 级截断；移动循环防护；备注行 localStorage 不写库
- 积累型误识别可手动改；打卡补打标记"补卡"
- 重复排期默认 30 天；「明天继续」保留原时长
- 全部操作带 userId（项目铁律）；Schedule 时间修改一律走 Schedule Service（铁律）
