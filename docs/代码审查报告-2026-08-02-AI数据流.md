# AI 数据流全链路审查报告（2026-08-02 第四轮）

> 范围：UI 输入 → 行为采集 → 记忆加工 → 画像存储 → LLM 上下文，整条 AI 运行链路 + 任务属性
> 验证：tsc 零错误 / vitest 29/29 / npm run build 成功

---

## 一、链路全景（审查后的真实数据流）

```
UI 操作 ──► 采集层 ──► 加工层 ──► 画像存储 ──► LLM 上下文
│             │            │            │            │
│ 创建/完成    UserObservation  pattern-mining(9规则)  AgentMemory  buildAgentContext
│ 暂停/跳过    TaskExecFeedback  memory-learning       UserPattern   +UserModel(新)
│ 拖动排期     AgentFeedback    memory-lifecycle      UserModel     client.ts prompt
│ 采纳/忽略    DecisionLog      advanced LLM 分析      UserProfile
│ 状态设置     TimeLog/DailySummary                   UserState(新:当日过期)
```

## 二、P0 级修复（5 项）— 链路断裂/数据丢失

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| P0-1 | **AgentMemory 双状态字段（active + status）状态机失效**：屏蔽/退休记忆只改 status，但 4 处查询用 active:true | **用户屏蔽的记忆仍被注入 LLM prompt**（隐私+正确性），两条读取路径结果不一致 | 统一查询为 `status:"active"`（4 处） |
| P0-2 | **pause 观察只写不读**：`type="pause"` 的 UserObservation 无任何加工 | 暂停行为采集了却从不学习 | 新增 pattern-mining **Rule 9**（按类别×原因统计暂停模式） |
| P0-3 | **拒绝/修改建议零采集**：recordRejectFeedback 无调用者 | 只能学到"全部接受"，反馈系统偏置 | Inbox「忽略」→ 拒绝反馈已接入 |
| P0-4 | **采纳建议零采集**：apply-decision 只 moveSchedule 不写任何反馈 | 最强正反馈完全丢失 | apply-decision 补写 agentFeedback(accepted) + decisionLog |
| P0-5 | **DecisionLog.userAccepted 无任何写入** → **trustScore 恒 0.5** | AI 自动执行能力（canAutoExecute）永不升级 | DecisionLog 支持 userAccepted；采纳/确认路径写入 |

## 三、P1 级修复（10 项）— 数据错误/闭环缺失

| # | 问题 | 修复 |
|---|---|---|
| P1-6 | mineCategoryBlocking 用中文"太难"匹配，系统 reason 是英文枚举 → **commonFailures 恒空** | 双匹配（too_hard/太难/太复杂） |
| P1-7 | user_adjust/user_reschedule 污染中断原因统计 | 统计排除 `user_` 前缀 |
| P1-8 | analyzeFeedback 匹配 "duration" 但写入是 "time" → 时长偏差规则永不触发 | 双匹配 |
| P1-9 | computeImportanceScore 无调用者 → **top-N 记忆排序退化为插入序** | daily pipeline 批量计算 |
| P1-10 | **UserModel 机器学习画像不进 LLM 上下文** | 新增 buildUserModelContext + prompt 注入（高效时段/容量/卡点/信任分） |
| P1-11 | commonFailures/taskChunk 算出但决策引擎不消费（死输出） | makeDecision 新增 Rule 2.5（分块偏好）+ 卡点命中理由 |
| P1-12 | **UserState.validUntil 永不写入 → 旧状态永不过期**（昨晚的"精力低"永远影响今日） | 写入时设当日 23:59:59 过期 |
| P1-13 | daily pipeline 仅访问 today 页触发 + 失败后重复跑（LLM 费用放大） | 入口先写 lastUpdated 防抖 |
| P1-16 | 任务创建/完成零采集 | task_create / task_complete observation |
| P1-17 | 记忆 source="user" 在冲突优先级表中是 0（输给 AI 分析） | SOURCE_PRIORITY 补 user(85)/ai(40)/feedback(50) |
| P1-18 | today-decide 的 DecideAction 与 decision/executor 类型不匹配（前端一接线就断） | interface 扩展 + executor 补 6 个映射实现（postpone/reduce_time/skip/swap/reduce_all/keep_mustdo_only） |

## 六、关键结论

1. **采集层 3 处确定性死数据已全部激活**（pause 规则、采纳反馈、拒绝反馈）
2. **信任分从"恒 0.5 死数据"变为可成长**（userAccepted 闭环打通）
3. **机器学习画像终于进 LLM 上下文**（之前 AI 只看到用户自述，看不到行为统计画像）
4. 状态过期机制从死代码变为生效（状态当日有效）
5. 整条链路"采集→加工→画像→上下文"四个环节全部闭合
