## 一、页面功能清单

### 0. 全局基础设施（所有页面的公共壳）

#### 0.1 根布局 `src/app/layout.tsx`
- **核心功能**：全站 Provider 挂载层（服务端组件）——`ThemeProvider`（主题四轴 context）+ `AuthProvider`（NextAuth `SessionProvider`）+ `PwaRegister`（PWA 注册），并配置 PWA manifest 与 Apple WebApp 元信息。
- **入口路径**：所有页面的祖先。
- **关键数据/模块**：`@/contexts/ThemeContext`、`@/components/auth-provider`、`@/components/pwa-register`。

#### 0.2 Dashboard 壳 `src/app/(dashboard)/layout.tsx` + `DashboardShell`
- **核心功能**：鉴权闸门 + 全局壳装配。未登录访问任意 Dashboard 页 → `redirect("/login")`；已登录渲染 `DashboardShell`（将 `session.user.name/email` 传入）。
- **壳内固定元素**：
  - **三种导航**：默认工作流侧栏 `Sidebar`（品牌行 + 全局搜索 + 5 个工作流导航项 Inbox→Plan→Today→Review→Projects，Today 带"默认"徽章 + 设置入口 + 用户退出；支持折叠 240px↔64px）；`Topbar` 顶栏形态（设置页可切换）；`MobileNav` 移动端底部 4 Tab 悬浮胶囊（`lg:hidden`）。
  - **`GlobalSearch`** 全局搜索（侧栏/顶栏内嵌，见 0.4）。
  - **`ArchiveProvider`** 全局挂载任务档案抽屉 `TaskArchivePanel`（右侧 560px），全站任意页面可 `useArchive().open(taskId, seed)` 打开。
  - **`ContentContainer`** 页面宽度规则：宽页（Today/Plan/Week/Projects/Review）1160px（顶栏模式 1280px），窄页（Inbox/Settings）720px。
  - 隐藏的 `#ai-assistant-slot` 插槽占位。
- **主要交互**：
  - **Ctrl+↑/↓ 页面切换**：按 `NAV_ORDER`（工作流 5 页 + /settings）循环跳页（输入框聚焦时不触发）。
  - 导航形态/语言即时切换（监听 `taskos:nav-change`/`taskos:lang-change` 事件）。
- **关键数据/模块**：`@/lib/auth`（auth() 会话）、`@/lib/navigation`（NAV_ITEMS/NAV_ORDER/isActiveNav）、`@/lib/ui-preferences`（taskos.nav/taskos.lang）、`DashboardShell`、`sidebar.tsx`、`nav/topbar.tsx`、`mobile-nav.tsx`、`ArchiveProvider`。

#### 0.3 根页 `src/app/page.tsx`
- **核心功能**：访问 `/` 无条件 `redirect("/today")` —— Today 是默认落地页。
- **入口路径**：`/`。
- **关键数据/模块**：`next/navigation` 的 `redirect`。无 UI、无交互。

#### 0.4 全局搜索 `src/components/search/GlobalSearch.tsx`
- **核心功能**：跨页面任务检索（标题/标签/归属链/最近排期），不跳页——点击结果直接打开任务档案面板。
- **主要交互**：输入防抖 250ms → 优先 `GET /api/tasks/search?q=`，失败降级拉 `GET /api/tasks` 本地 contains 过滤；`⌘K/Ctrl+K` 聚焦、Esc 关闭。
- **入口路径**：侧栏 / 顶栏内嵌，全站可见。
- **关键数据/模块**：`/api/tasks/search`、`useArchive()` context。

#### 0.5 登录 / 注册页 `src/app/(auth)/login/page.tsx` + `register/page.tsx`
- **核心功能**：全宽横版认证页（左品牌区 7fr：Logo + Slogan"你的时间，自有中轴。" + 品牌故事 + 价值三卡 + 成长闭环流程条；右表单区 5fr，渐变背景）。
- **主要交互**：
  - 登录：邮箱+密码 → `signIn("credentials", { redirect:false })` → 成功 `router.push("/today")` + `router.refresh()`；失败提示"邮箱或密码错误"。
  - 注册：昵称+邮箱+密码（≥6 位）→ `POST /api/auth/register` → 成功跳 `/login`。
  - 占位 UI（未接入）："记住我"、"忘记密码？"、微信/Google 登录按钮。
- **入口路径**：未登录访问 Dashboard 任意页被重定向至 `/login`；注册经登录页"立即注册 →"。
- **关键数据/模块**：`next-auth/react`（signIn）、`POST /api/auth/register`（bcrypt 哈希 + 注册后异步注入基线记忆）、`@/lib/auth`（Credentials 配置含内存滑动窗口限流：同邮箱 15 分钟最多 5 次失败）、`AuthBrand`/`MeridianLogo`。

### 1. Inbox 收件箱 `/inbox`（工作流第 ① 步：收纳）

- **页面类型**：客户端组件。
- **核心功能**：自然语言任务收集箱。把脑中杂事倒进来，AI 解析为结构化任务（分类/主题/类型/预估/截止/动机/置信度），复杂任务自动阶段拆解，确认后批量创建任务。
- **主要交互操作**：
  - 输入 → Enter / 点"AI 整理" → `POST /api/inbox/analyze`（AI 优先 + 规则降级，始终返回可用结果）→ 展示整理卡片与 AI `understanding` 摘要。
  - 每张卡：**确认**（单条创建）/ **编辑**（EditPanel 真编辑：标题/备注/领域 7 类 chips/主题预设+自定义色/动机≤50字/预估/重要性/子任务）/ **忽略**（移除并 `POST /api/agent/feedback` 发 `inbox_analyze` + `rejected` 负反馈）。
  - 简单卡快捷操作：**＋加子任务** / **设为每天**（accumulate 积累型）/ **设有截止** / **重要性三档**。
  - **全部创建**（批量 confirm）/ **全部忽略**；创建后**撤销**（逐个 `POST /api/tasks/[id]/action` action=delete）。
  - 快捷键：Enter 发送、Shift+Enter 换行、Esc 取消输入。
- **入口路径**：侧栏①收纳 → `/inbox`。
- **关键数据/模块**：API `POST /api/inbox/analyze`、`POST /api/inbox/confirm`、`POST /api/agent/feedback`、`POST /api/tasks/[id]/action`；**localStorage `taskos.inbox.draft` 草稿持久化（24h 有效，切页不丢，恢复显示"上次未完成"徽章）**；lib：`@/lib/plan/colors`、`@/lib/task/theme`、`@/lib/task/estimate`、`@/types/inbox`；组件 `ThemeBadge`。
- **⚠️ 异常标注**：无功能缺失；依赖 AI 可用性（无 AI 配置时走规则降级解析）。

### 2. Plan 规划页 `/plan`（工作流第 ② 步：规划）

- **页面类型**：客户端组件。
- **核心功能**：周计划甘特图（周历时间轴 8:00 起 · 68px/小时）+ 本周截止看板 + 收集箱（未排期任务）+ 续排建议 + 计划健康度。
- **主要子组件**：`WeekCalendar`（时间轴甘特图 + 实时时间线 + 凌晨折叠 + 分类/主题图例）、`CollapseSection`（折叠条）、`ContinuationBar`（续排建议条）、`DeadlineBody`（本周截止卡组）、`IdeaPool`（收集箱拖拽源）、`TaskDetailPopover`（详情浮层，点击位置弹出自动翻转）、`ScheduleModalInner`（排期弹窗）。
- **主要交互操作**：
  - **周/聚焦胶囊切换**：聚焦 = 今天+未来两天，显示粉色实时时间线（每分钟刷新）；**周切换** ←/→ 调 `weekOffset`。
  - **拖拽排期**：任务块/收集箱项拖到天列，按鼠标 Y 坐标精确到半小时间隔 → `POST /api/plan/apply-decision`（带 scheduleId 只替换目标条防重复）。拖拽协议：`effectAllowed="copyMove"` + dataTransfer `text/task-id`。
  - **任务块点击** → 详情浮层：子任务勾选、追加子任务、开始/完成、调整时间、从计划移除（保留任务）。
  - **续排建议**"复制到明天" → `POST /api/tasks/[id]/action` action=`continue_tomorrow`。
  - **展开凌晨**（22:00-02:00 折叠区）、跨夜任务"⋯ 跨夜"提示；移动端 <860px 自动切聚焦 3 列。
- **入口路径**：侧栏②蓝图 → `/plan`；历史路由 `/week` 重定向至此；宽页面。
- **关键数据/模块**：API `GET /api/views/week-calendar?weekStart=`、`POST /api/plan/analyze`（健康分）、`GET /api/plan/continuations`、`POST /api/plan/apply-decision`、`POST /api/plan/delete`、`GET /api/tasks/[id]`、`POST /api/tasks/[id]/action`、`POST /api/tasks`；监听 `meridian-task-changed` 静默刷新；lib：`@/lib/plan/colors`、`@/lib/plan/time`（凌晨 0-2 点视觉归天）、`@/lib/date`、`@/lib/task/time-state`；算法：`assignLanes` 重叠轨道分配、`loadColor` 负荷三色条、`deadlineStats` 7 天梯度。
- **⚠️ 异常标注**：`/api/plan/repeat` 服务端已就绪但**无前端消费**（注释标注"已知未接线"）；健康分沉底折叠条默认收起。

### 3. Today 执行页 `/today`（工作流第 ③ 步：执行，默认落地页）

- **页面类型**：客户端组件（使用 `useSession` 显示用户名问候）。
- **核心功能**：今日执行驾驶舱 —— Focus Card V2 启动台（当前任务/必做任务轮播）+ 今日路线时间线 + AI 调整助手 + 今日状态自我汇报 + 完成/专注统计。
- **主要子组件**：
  - **`FocusCardV2`**（`src/components/today/FocusCardV2.tsx`）：核心执行卡，5 区布局（A 动机行→B 行动区→C 执行工具→D 回来确认→E 元信息行），4 态状态机（unstarted→going→confirm→done），5 类型（timer 固定时间 / checklist 清单 / learning 学习 / accum-daily 积累每日 / accum-weekly 积累频次）；内置弹窗 `DurationModal`（补记时长）/ `PauseModal`（暂停原因 5 项）/ `CheckinModal`（打卡内容）/ `MonthCal`（当月打卡小日历）；出发 ≥4h 未确认出"忘记确认"警示条。卡片形态由数据推断（有子任务→清单型 / 有排期→计时型 / 否则→学习型 / accumulate→积累型）。
  - `StatusBar`（今日状态折叠条：精力/专注/情绪/压力 4 维）、`RouteCard`（今日路线，点击切 Focus Card，hover"提前执行"）、`AiPanel`（AI 调整助手：建议列表采纳 + 底部对话输入）。
- **主要交互操作**：
  - Focus Card 主按钮：**出发**（start，写 departureAt）→ **该项完成**（补记时长弹窗 → complete+durationMinutes）/ **打卡**（accumulate → checkin+detail）/ **跳过** / **暂停**（pause+reason 5 项）/ **明天继续**（continue_tomorrow）。
  - 清单：子任务勾选（complete/reopen 切换）、**＋新增项**（乐观更新：先本地插 `tmp-` 项 → POST 落库 → 失败回滚）。
  - 轮播：左右箭头/圆点切换卡片；今日路线点击项 → 前置为轮播首卡。
  - AI 助手：**采纳建议**（如"5 分钟后开始"→ `POST /api/plan/apply-decision` 写排期）；**对话输入** → `POST /api/agent/chat`（LLM 对话 + 工具执行）。
  - 今日状态：折叠条展开 → "调整" → 4 维三选一 → `POST /api/user-state`。
  - 空态：去 Inbox / 去 Plan 两个引导 Link。
- **入口路径**：侧栏③此刻 → `/today`；根页 `/` 重定向至此；宽页面。
- **关键数据/模块**：API `GET /api/views/today`（**大聚合**：currentTask/nextTask/mustDo/recommended/alerts/brief/currentState/todayStats/todayTimeline/executionPattern/executionAdvice，GET 时触发惰性结算 + 异步 AI pipeline）、`GET /api/projects/tree`（页面级缓存只请求一次）、`POST /api/tasks/[id]/action`、`POST /api/tasks/[id]/checkin`、`POST /api/user-state`、`POST /api/plan/apply-decision`、`POST /api/agent/chat`、`POST /api/tasks`、`PUT /api/tasks/[id]`（保存备注）；监听 `meridian-task-changed`；lib：`@/lib/plan/colors`、`@/lib/task/time-state`、`@/lib/task/execution` 等。
- **⚠️ 异常标注**：Focus Card 左栏项目阶段（stages/projectProgress）当前为 mock 数据，待直读项目树 API。

### 4. Review 复盘页 `/review`（工作流第 ④ 步：复盘）

- **页面类型**：客户端组件。
- **核心功能**：本周/本月复盘报告：战报卡（周摘要+主色+之最+关键词+发现条）+ 北极星指标卡 + 主题投入 + 本周成果产出日记 + 本周洞察（时段偏好/打断）+ 下周建议（AI 可应用）。
- **主要子组件**：`ReportCard`（战报卡：规则聚合 + DailySummary 文案）、`MetricCards`（2×2：周完成率/AI 采纳率/堆积率/打卡保持率）、`ThemeInvestment`（主题投入 + 周环比趋势）、`DayDiary`（产出日记：按天分组 + 深度专注/分 N 段标签 + 图例）、`WeekInsight`（本周洞察：分类×时段 24-bin 滑动 3 小时窗口 + 打断注意）、`NextSuggestions`（下周建议，逐条应用）。
- **主要交互操作**：
  - **本周/本月分段切换** → `GET /api/views/stats?range=week|month`。
  - **应用建议** → `POST /api/agent/memory`（memoryType="preference" 写入长期记忆），按钮变"已应用 ✓"。
  - 其余为只读数据展示。
- **入口路径**：侧栏④复盘 → `/review`；宽页面，<860px 单栏回退。
- **关键数据/模块**：API `GET /api/views/stats?range=`（dailyBreakdown/totalCompleted/totalMinutes/behavioral{peakHours,efficiencyByTag,weekOverWeek,procrastinationRate}/completedTasks/periodBoundaries/metrics/themeBreakdown{含 prev 周环比}）、`POST /api/agent/memory`；lib：`@/lib/plan/colors`、`@/lib/task/periods`（日分区边界）、`@/lib/ai/daily-summary`；计算逻辑：关键词过滤系统 tag（`^(domain|important|ai|taskType|source|auto|schedule|deadline):`）、最投入任务按 timeLogs 求和、"本周主色"按分类时间占比。
- **⚠️ 异常标注**：主题投入的周环比（`prev` 字段）后端已就绪，前端目前显示"—"待切换展示。

### 5. Projects 项目页 `/projects`（工作流第 ⑤ 步：整理）

- **页面类型**：客户端组件（使用 `useArchive`）。
- **核心功能**：项目整理页（大纲式层级树：分组头 lvl0 / 阶段·积累 lvl1 / 任务 lvl2，连接线+层级圆点）。左侧项目树 + 右侧三区（待整理池 / 习惯打卡区 / 归档）。
- **主要交互操作**：
  - **节点点击** → `openArchive(node.id)` 打开全局档案面板。
  - **拖拽**：行到节点 = 成为子级；行间 = 换序（before/after/child 三区判定）；树拖回待整理池 = 解挂载；池项拖到树空白 = 自动新建项目并挂入（先 POST 建项目再 move）。拖拽协议：`text/plain` + `application/x-task-source`（"tree"/"pool"）。
  - **新建**：`＋ 新建项目` / 行尾 `＋` 新建子项（inline input，按 parent level 自动推断 project/phase/task）。
  - **★ 执行清单开关**（乐观更新 + `PUT /api/tasks/[id]` 落库 + 广播 `meridian-task-changed`）。
  - **同级排序**：行尾 ↑↓ 按钮（遍历兄弟节点 moveNode 带 sortOrder）。
  - **待整理池**：AI 建议归属（后端 suggestion / 前端推断主题匹配）→ "挂入"一键挂入或新建项目；池项有"已排期到 Plan"透明化提示。
  - **习惯区打卡（全站打卡唯一入口）**：`POST /api/tasks/[id]/checkin`，7 日周点 + 连续天数；树行只留金色状态点（今日已打卡/未打卡）。
  - **归档**：折叠区展示已完成任务（树内+孤儿）；展开/收起行首 ▾/▸。
- **入口路径**：侧栏⑤项目 → `/projects`；支持 `?highlight=taskId`（档案面板"去 Project 定位"跳转，**见异常标注**）。
- **关键数据/模块**：API `GET /api/projects/tree`（trees/orphans + 完成度聚合/派生色/建议归属/streak）、`POST /api/projects/move`、`GET /api/tasks/[id]/streak`（习惯区逐任务并发拉取）、`POST /api/tasks/[id]/checkin`、`PUT /api/tasks/[id]`、`POST /api/tasks`；`useArchive()` context；监听 `meridian-task-changed`；lib：`@/lib/plan/colors`、`@/lib/project/suggestion`、`@/lib/project/theme-color`。
- **⚠️ 异常标注**：见全局问题 #1（`?highlight=` 参数无人消费，档案面板"去 Project 定位"跳转后不会滚动定位）。

### 7. 设置页 `/settings`

- **页面类型**：客户端组件（使用 `useSession`/`signOut`）。
- **核心功能**：控制面板 + 信任校准。四大分组：我的身份 / 我的时间 / AI 的控制权 / 数据主权（+ 界面组 + 关于）。
- **主要子组件**：`Group`/`Card`（折叠卡，默认只开第一组）/`Row`/`Switch`/`Seg` 原子组件；`AccountCard`（账户资料）、`TimeCard`（时间与作息：起床/睡觉、精力高峰/低谷、固定时间块 CRUD、可用时间段 CRUD、**日分区边界 4 格行内编辑**）、`AiControlCard`（AI 控制中心：总开关/4 角色开关/建议力度/改动需确认）、`AiMemoryCard`（AI 对我的理解：信任分 + 记忆列表关闭/恢复）、`AiConfigCard`（AI 服务配置：OpenAI/通义千问/DeepSeek V4/自定义 4 预设 + 测试连接）、`DataCard`（数据与隐私：三统计格 + 导出 JSON + 清理学习数据 + 删除账户）、`AboutCard`（品牌 + 版本）、`NavLayoutSettings`（导航与版式：导航方案/导航语言/Focus Card 版式，改动即时生效）。
- **主要交互操作**：
  - 昵称保存 → `PUT /api/user` + `update()` 刷新 session；退出登录 → `signOut({ callbackUrl: "/login" })`。
  - 作息保存 → `PUT /api/agent/profile`（10 个白名单字段）；**日分区边界编辑** → 写 `preferences.periodBoundaries`（与 Review 时段偏好/Plan 分区背景共用）。
  - AI 控制开关 → 全部存 localStorage（`taskos.ai.master/roles/level/confirm`）。
  - 记忆管理 → `GET/POST /api/agent/memory/dashboard`（block/unblock）。
  - AI 配置 → `GET/PUT /api/ai-config` + `POST /api/ai-config/test`（连接延迟显示）。
  - **导出 JSON**（数据主权）→ 聚合 `GET /api/views/stats` + `/api/agent/memory/dashboard` + `/api/views/week-calendar`，`buildExportHeader` 加 `schemaVersion:2` + 迁移映射表，Blob 下载 `taskos-backup-YYYY-MM-DD.json`。
  - **清理学习数据** → `POST /api/user?action=cleanup`（保留任务）；**删除账户** → `DELETE /api/user`（双重 confirm，成功后 signOut）。
  - 导航/版式切换 → 写 localStorage + window 事件广播（`taskos:nav-change`/`taskos:fclayout-change`/`taskos:lang-change`），壳与 Today 即时响应。
- **入口路径**：侧栏底部"设置"/顶栏齿轮 → `/settings`；窄页面 720px。
- **关键数据/模块**：`@/lib/date`、`@/lib/task/periods`（PERIOD_KEYS/PERIOD_LABELS/DEFAULT_BOUNDARIES）、`@/lib/export-version`、`@/lib/ui-preferences`、`@/components/settings/nav-layout-settings`。
- **⚠️ 异常标注**：登录页与设置页的第三方登录入口均为占位；AI 配置"不配置也能用"（规则引擎降级）为有意设计。

## 二、信息联动效果整理

> 项目**没有全局状态 store**（无 zustand/redux/swr）。联动依赖三类机制：
> ① **window CustomEvent 广播**（跨页刷新总线）② **各页自持 state + 动作后重新 fetch**（页内总线）③ **localStorage + 事件**（偏好即时生效）。另有服务端"读时结算"与定时任务两类隐藏联动。

### 联动 1：全站写操作刷新总线 `meridian-task-changed`（跨页核心）

| 项 | 说明 |
|---|---|
| **触发条件** | 档案面板 4 处写操作成功（保存编辑 / 补记时长 / 重开 / 删除）+ Projects ★执行清单开关 |
| **来源 → 目标** | `TaskArchivePanel` / Projects 页 → **Today 页**（重取今日视图）、**Plan 页**（重取周历 + 续排建议）、**Projects 页**（重取树） |
| **数据传递** | `window.dispatchEvent(new CustomEvent("meridian-task-changed"))` → 各页 `addEventListener` 后调各自 `load()` 静默重取（Plan/Projects 静默，Today 全量） |
| **效果** | 在任何页面编辑任务身份（主题/领域/动机）或删除任务，其他页面的卡片/时间块/统计即时同步 |

### 联动 2：Today 单页总线（动作 → 重取 → 全组件联动）

| 项 | 说明 |
|---|---|
| **触发条件** | Focus Card 一切动作：出发/完成/打卡/跳过/暂停/明天继续、清单勾选/新增、采纳 AI 建议、保存今日状态 |
| **来源 → 目标** | FocusCardV2/RouteCard/AiPanel/StatusBar（子组件）→ Today 页 `data` state → 全部子组件派生刷新 |
| **数据传递** | 子组件 props 回调上抛（onStart/onComplete/onItemToggle/onCheckin/onPause/onContinueTomorrow）→ 页内 `await load()` 重取 `GET /api/views/today` → 单一 `data` state 驱动卡片/统计徽章/路线/建议同步 |
| **效果** | 完成一项 → 统计徽章（completedCount/totalMinutes）与轮播下一张卡同步变化；打卡 → 月历打卡点即时点亮 |
| **细节** | 清单新增项为**乐观更新**（本地先插 `tmp-` 项再落库，失败回滚）；卡片内部仅本地模拟 phase，`card.phase` 变化经 `useEffect` 与外部同步 |

### 联动 3：Plan 页联动（拖拽/弹窗/浮层 → 静默刷新）

| 项 | 说明 |
|---|---|
| **触发条件** | 拖拽排期落位、排期弹窗确认、详情浮层开始/完成、从计划移除、续排"复制到明天" |
| **来源 → 目标** | WeekCalendar 拖拽回调 / TaskDetailPopover / ContinuationBar → Plan 页 `load(true)`（静默，不切骨架屏、保滚动位置）+ `loadContinuations()` |
| **数据传递** | 组件回调 → 页内状态 → `POST /api/plan/apply-decision` 等 API → `load(true)` 重取 `GET /api/views/week-calendar` + `POST /api/plan/analyze` |
| **效果** | 拖入新任务块即时上墙；"复制到明天"后明天时间块出现、建议条移除；实时时间线每分钟自刷新（纯视觉，60s interval） |
| **细节** | 拖拽带 `scheduleId` 只替换目标条，防重复排期 |

### 联动 4：Projects 页联动（树与待整理池）

| 项 | 说明 |
|---|---|
| **触发条件** | 节点拖拽（移动/解挂载/换序）、★开关、习惯区打卡、挂入建议 |
| **来源 → 目标** | 树/池组件 → Projects 页 → 本地树 state 乐观更新 + `POST /api/projects/move` / `PUT /api/tasks/[id]` / `POST /api/tasks/[id]/checkin` 落库 |
| **数据传递** | React state（乐观）→ API → 失败回滚；★开关额外广播 `meridian-task-changed` 通知其他页 |
| **效果** | 拖拽换父级即时重绘连接线；打卡后树行金色状态点 + 习惯区周点/连击数同步更新 |

### 联动 5：Inbox → 任务库（创建链路）

| 项 | 说明 |
|---|---|
| **触发条件** | 确认草稿（单条/全部创建） |
| **来源 → 目标** | Inbox 页 → `POST /api/inbox/confirm`（confirm-service 批量建任务+排期）→ 任务库；同时"忽略"操作写 `agentFeedback`（rejected）回流 AI 学习 |
| **数据传递** | API 调用；草稿本身经 localStorage `taskos.inbox.draft` 跨页面/跨会话持久（24h） |
| **效果** | 新任务流入 Plan 收集箱 / Today 建议；Inbox 撤销动作反向删除刚建任务 |

### 联动 6：全局搜索 ↔ 档案面板 ↔ 各页

| 项 | 说明 |
|---|---|
| **触发条件** | 搜索框输入（防抖 250ms）→ 点击结果 |
| **来源 → 目标** | GlobalSearch → `useArchive().open(taskId, seed)` → 档案抽屉打开（560px 右侧）→ 编辑保存后广播联动 1 |
| **数据传递** | React context（`ArchiveProvider` 挂载于 DashboardShell，全站可用）+ props（taskId/seed） |
| **效果** | 任意页面按 ⌘K 搜索 → 打开档案 → 编辑 → 全部页面同步；档案面板是全站唯一的"任务身份编辑 + 删除"入口 |

### 联动 7：偏好设置广播（设置页 → 壳/Today 即时生效）

| 项 | 说明 |
|---|---|
| **触发条件** | 设置页更改导航方案/导航语言/Focus Card 版式 |
| **来源 → 目标** | `NavLayoutSettings` → localStorage（`taskos.nav`/`taskos.lang`/`taskos.fcLayout`）+ window 事件（`taskos:nav-change`/`taskos:lang-change`/`taskos:fclayout-change`）→ DashboardShell（切侧栏/顶栏）、三种导航（语言切换）、Today（版式切换） |
| **数据传递** | localStorage（持久化）+ CustomEvent（同页即时广播） |

### 联动 8：AI 控制中心（设置页 → 全站 AI 行为，无 UI 联动但有行为联动）

- **触发条件**：设置页切换 AI 总开关/角色开关/建议力度/改动需确认。
- **来源 → 目标**：设置页 → localStorage `taskos.ai.master/roles/level/confirm` → 各页 AI 面板（Today AiPanel、Inbox 解析、Plan 建议）消费开关决定是否展示 AI 功能。
- **数据传递**：localStorage（无事件广播，页面加载时读取）。

### 联动 9：服务端隐藏联动（读时结算 + 定时任务）

| 项 | 说明 |
|---|---|
| **惰性结算** | `GET /api/views/today` 打开时触发 `lazySettleExpiredScheduled`：过期未完成的 scheduled 任务**自动标记完成**（写 task + timeLog(type='auto', detail='auto') + decisionLog），幂等。→ 用户打开 Today 页即看到"过期任务自动收尾"，Review/统计随之变化 |
| **daily-cron** | 服务器 5 分钟检查、每天 05:00 执行：注入基线记忆 → 解冻过期 snoozed 任务 → 每日 AI pipeline（pattern-mining + 记忆衰减 + 画像）→ 清理 90 天前决策日志。→ 从"依赖用户打开页面"的门铃模式改为服务端主动 |
| **数据单向链** | Today 打开 → 生成 dailySummary/todayDecision/异步 pipeline → Review 消费（stats/洞察）+ Plan 消费（高效时段/健康分）。链路：**操作（各页）→ 落库（task/schedule/timeLog/feedback/observation）→ 聚合视图（today/stats/week-calendar）→ 各页展示** |

### 联动 10：跨页跳转类

| 触发条件 | 来源 → 目标 | 传递方式 |
|---|---|---|
| 登录成功 | login → `/today` + `router.refresh()` | 路由跳转 |
| 注册成功 | register → `/login` | 路由跳转 |
| Ctrl+↑/↓ | DashboardShell → 按 NAV_ORDER 循环跳页 | 路由跳转（输入框聚焦时禁用） |
| 档案面板"去 Project/去 Plan" | TaskArchivePanel → `/projects?highlight=id` / `/plan?highlight=id` | 路由跳转 + query 参数（**目标未消费，见问题 #1**） |
| 空态引导 | Today 空态 → `/inbox`、`/plan` | 路由跳转 |

## 三、项目整体结构简要总结

### 3.1 架构形态

```
src/
├── app/
│   ├── page.tsx                    # / → redirect /today
│   ├── (auth)/login|register/      # 认证页（无壳，全屏）
│   ├── (dashboard)/
│   │   ├── layout.tsx              # 鉴权闸门 + DashboardShell（三种导航/搜索/档案抽屉/宽度规则）
│   │   ├── inbox/ plan/ today/ review/ projects/   # 工作流五页面
│   │   ├── week/                   # 历史路由 → redirect /plan
│   │   └── settings/               # 控制面板 + 信任校准
│   └── api/                        # 44 个 API 路由（auth/ai/inbox/plan/tasks/decision/agent/views/projects/user 九大模块）
├── components/                     # 40 个组件（today/FocusCardV2、task/档案面板、search/GlobalSearch、nav、auth、ui 原子）
├── lib/                            # 70+ 服务（plan/ai/inbox/task/schedule/project/user-state/context）
├── prisma/                         # schema（20 表）+ 迁移
└── tests/                          # vitest 95 用例
```

### 3.2 数据流单向链（核心架构理念）

```
Inbox 收纳 ──AI解析──▶ Task/Schedule 落库 ◀──Plan 拖拽排期
                              │
                    Today 执行（写 action/timeLog/checkin/user-state）
                              │
                    Review 复盘（读 stats/摘要/行为洞察，回写记忆）
                              │
                    AI 增强（feedback/observation/memory → trustScore → 建议质量提升）
```

- **唯一时间数据源**：`Schedule` 表；Task 不存时间字段，改时间必须走 Schedule 服务。
- **状态白名单**：任务状态变更必须走 `POST /api/tasks/[id]/action`（13 种 action），禁止直写。
- **学习闭环**：用户操作（accept/reject/modify）→ `agentFeedback`/`userObservation`/`decisionLog` 三张学习表 → trustScore 与 pattern-mining → 反哺建议。
- **零 AI 依赖核心**：today-decide（今日决策）、pause-advisor、execution-advisor、plan 冲突分析、项目归属建议均为纯规则引擎，无 AI 配置也能完整运行。
- **前端无全局 store**：依赖 window 事件 + 各页自取数据 + localStorage 偏好，页面间实时性由 `meridian-task-changed` 总线保证。

### 3.3 API 模块速览（44 个）

| 模块 | 数量 | 代表 | 写库 |
|---|---|---|---|
| auth | 2 | register、[...nextauth] | 注册建用户 |
| ai | 3 | parse（LLM）、today-decide（规则）、plan（LLM 排期） | plan 写排期 |
| inbox | 2 | analyze（LLM）、confirm | 建任务 |
| plan | 7 | apply-decision、delete、continuations、analyze、decision、repeat、task/[id] | 排期增删改 |
| tasks | 12 | 增删改查、search、action（状态机）、checkin、timer、time-log、timeline、exec-state | 任务/时间日志 |
| decision | 2 | analyze（LLM 顾问）、confirm（执行） | 按动作写库 |
| agent | 9 | chat（LLM+工具）、memory、profile、state、feedback、context、confirm | 记忆/画像/反馈 |
| views | 4 | today（大聚合+懒结算）、stats、week-calendar、today/refresh | GET 含副作用 |
| projects | 2 | tree、move | 移动节点 |
| user/其他 | 5 | user、user-state、daily-note、ai-config(+test) | 用户/配置 |

## 四、异常与待完善标注汇总

### 断链 / 未接线（代码层面确认）

1. **`?highlight=` 参数无人消费（断链）**：档案面板"去 Project 定位"跳转 `/projects?highlight=taskId`、"去 Plan"跳转 `/plan?highlight=taskId`，但两个目标页面**均无 useSearchParams 消费**——跳转后不会滚动/高亮定位目标任务。
2. **`POST /api/views/today/refresh` 无前端调用**：今日决策强制刷新接口已就绪，但全库搜索无任何 fetch 指向它（预留/手动入口）。
3. **`POST /api/plan/repeat` 未接线**：重复任务批量排期接口存在，无前端消费（注释自标"已知未接线"）。
4. **`lib/ai/today.ts`（getTodaySuggestion）无引用**：疑似旧版 Today 建议逻辑遗留文件。

### 占位 / 在位但不活跃

5. **主题系统（ThemeContext + ThemeSwitcher）在位但不活跃**：基础设施完整（四轴主题 + localStorage + v2 迁移），但 UI 入口已被摘除（品牌定稿 D19 决定不做用户自定义配色），全项目无任何文件 import `ThemeSwitcher`。
6. **登录页占位 UI**："记住我"、"忘记密码？"、微信/Google 登录按钮均为占位，未接入真实能力。

### 已知遗留（对照开发记忆，前端待对接）

7. **Review 主题趋势周环比**：`prev`（上周同主题任务数/占比）后端已就绪，前端目前显示"—"待切换展示。
8. **Focus Card 左栏项目阶段（stages/projectProgress）**：当前为 mock 数据，待直读项目树 API。
9. **导出仅聚合视图**：导出 JSON 为统计/记忆/周历聚合，任务明细（全量 Task）尚未包含。
10. **忘记确认提示条**：基于 departureAt 的"忘记确认"警示（Focus Card V2 已有出发≥4h 警示，服务端惰性结算兜底，部分提示形态待前端补充）。
11. **mini-cal 迁入 V2 右栏**：计划中未实施。
12. **pattern-mining Rule11 动机达成反馈**：观察 purpose 数据积累后实施。

### 设计特性（非缺陷，标注以免误判）

- `GET /api/views/today` 与 `GET /api/views/stats` 带写副作用（懒结算/异步分析）——"读时结算"模式，属有意设计。
- AI 未配置时全站自动降级为纯规则引擎（"不配置也能用"）。
- 页面切回（visibilitychange/focus）不会自动刷新数据——实时性依赖事件总线和手动操作，属当前取舍。
