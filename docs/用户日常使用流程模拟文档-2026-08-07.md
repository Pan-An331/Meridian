# 用户日常使用流程模拟文档

> 版本：V1.0 ｜ 日期：2026-08-07 ｜ 依据：Meridian（Task OS）现有已实现功能  
> 用途：功能演示与验收依据（按真实用户一天自然使用时间线，逐环节给出操作步骤、页面、核心功能、FocusCard 交互、衔接与数据流转）  
> 说明：本文档仅描述已实现功能；未实现项均以「⚠️ 现状」明确标注，不虚构能力。



---

## 0. 核心概念速览（阅读前置）

### 0.1 工作流五页 + 设置

`Inbox（收纳·理解）→ Plan（蓝图·规划）→ Today（此刻·执行）→ Review（复盘·学习）→ Projects（项目·整理）`

### 0.2 FocusCard 四款（Today 执行页主卡）

| 卡片      | 类型标识                       | 触发条件（自动推断）             | 核心语义            |
| ------- | -------------------------- | ---------------------- | --------------- |
| **清单型** | checklist                  | 任务**有子任务**（执行清单）       | 以产出清单为准，计时是辅助   |
| **学习型** | learning                   | **无子任务且无排期**           | 勾知识点，可逆推进       |
| **时间型** | timer                      | **有排期且无子任务**           | 上课/开会/吃饭，到点自动完成 |
| **积累型** | accum-daily / accum-weekly | 任务为**积累型**（accumulate） | 每日打卡/频次坚持，中断从头数 |

**通用状态机（四卡共用）**：`未出发 → 出发中 → 回来确认 → 已完成`；四态驱动主按钮与状态标签变化。

### 0.3 一个信息只有一个「家」

身份（Inbox 定）→ 结构（Project 管）→ 时间（Plan 管）→ 执行（Today 产生）→ AI 增强（全自动）。

## 1. 环节一 ｜ 07:40 通勤路上 · 随手录入今日事项

| 维度        | 内容                                                    |
| --------- | ----------------------------------------------------- |
| **时间点**   | 07:40（通勤/排队等碎片时间，5-8 分钟）                              |
| **页面/模块** | `Inbox 收件箱`                                           |
| **核心功能点** | AI 理解整理（LLM，失败自动降级关键词规则）、简单卡/复杂卡、批量确认/全部忽略、撤销删除、草稿持久化 |

### 操作步骤

1. 打开应用 → 落地 `Today` → 左侧导航点击「收纳」进入 Inbox。
2. 在输入框（"把脑子里的事倒进来…"）分两行粘贴/输入今日事项，例如：
   - `完成产品需求评审文档，预计 90 分钟`
   - `给导师发实验数据，预计 30 分钟`
   - `晚上健身 45 分钟，每周三次`
3. 点击「AI 整理」→ 等待结果（AI 正常 3-5s；异常时自动走「关键词降级解析」，体验等价）。
4. 检查整理结果卡片：
   - 简单卡：标题/领域/预计时长已结构化 → 点「确认」创建（卡片变「撤销」态，误触可撤销）。
   - 复杂卡（AI 判定含阶段/子任务）：显示「确认创建 N 个子任务」→ 确认后批量落库。
5. 若有不想要的项 → 卡片「忽略」；全部不需要 → 「全部忽略」。

### FocusCard

**无**（本环节为录入阶段，不进入执行卡）。

### 衔接与数据流转

- Inbox 输入 → AI 整理 → 确认 → `Task` 落库（含 category 领域 / estimatedMinutes 预计 / theme 主题 / purpose 动机 / 子任务 children）。
- 已确认任务即离开 Inbox 结果区；**刷新页面草稿仍在**（localStorage 草稿持久化），可中断续录。
- **数据流向下一环节**：任务以「未排期」身份进入 Plan 收集箱的候选池（★ 任务）与 Projects 待整理池（孤儿）。

## 2. 环节二 ｜ 08:00 早餐 · 精细调整优先级与截止日

| 维度        | 内容                                  |
| --------- | ----------------------------------- |
| **时间点**   | 08:00（确认前的最后调整窗口，3-5 分钟）            |
| **页面/模块** | `Inbox 收件箱`（整理结果卡片上的快捷动作区）          |
| **核心功能点** | 重要性三档（低/中/高）、设有截止、设为每天（积累型开关）、＋加子任务 |

### 操作步骤

1. 在待确认的卡片上：
   - **调优先级**：点击卡片内「低 / 中 / 高」按钮（1-5 档映射为三档），当前档高亮 → 即改即存（onModify importance）。
   - **调截止日**：点击「设有截止」→ 日期选择器 → 确定 → 卡片出现「截止 MM/DD」徽标。
   - **设积累**：点击「设为每天」→ 变为「✓ 每天重复」（accumulate=true，后续 Today 以积累卡呈现）。
   - **拆子任务**：点击「＋ 加子任务」→ 输入子项 → 简单卡升级为复杂卡（快捷按钮区随之变化）。
2. 确认创建（进入环节一的第 4 步流程）。

### ⚠️ 现状（如实标注）

- **截止日编辑入口目前仅存在于 Inbox 确认前**；任务创建后档案面板的截止日为只读展示（无编辑按钮）——「调整已有任务的截止日期」在创建后暂无 UI 入口，属已知缺口（BUGS.md 待办区相邻项），验收时按"确认前可调"为准。

### FocusCard

**无**。

### 衔接与数据流转

- 调整项随确认一并落库：`importance`（低1-2/中3/高4-5）、`deadline`（ISO 本地 23:59）、`accumulate`、`children`。
- **数据流向下一环节**：带截止日的任务成为 Plan「本周截止」统计来源；积累型任务进入 Projects 习惯区候选；★ 任务进入收集箱。

## 3. 环节三 ｜ 08:15 到工位 · 项目归类与「布置」

| 维度        | 内容                                                              |
| --------- | --------------------------------------------------------------- |
| **时间点**   | 08:15（5 分钟）                                                     |
| **页面/模块** | `Projects 项目整理`                                                 |
| **核心功能点** | 项目树（project→phase→task 层级）、待整理池 AI 建议归属、拖拽挂树/解挂载、★ 执行清单、习惯区、归档区 |

### 操作步骤

1. 左侧导航进入「项目」→ 右栏「待整理池」显示 Inbox 确认后未挂树的孤儿任务（含 AI 建议归属文案，如「AI 建议 → 挂入 XX 项目」）。
2. **归类**：将任务拖拽到左侧项目树的目标节点上（成为其子级）；或点击待整理池行内「挂入」按钮按 AI 建议归属；拖到树区空白会自动新建主题匹配项目并挂入。
3. 若项目不存在：点「＋ 新建项目」→ 输入名称回车。
4. **布置（执行清单）**：对今天要执行的任务点击行尾 ★ → 变亮「执行清单」标记（乐观更新 + PUT 落库）。
5. 顺手查看：习惯区（积累型打卡唯一入口）、归档区（已完成任务）。

### ⚠️ 现状（如实标注）

- **本产品为单用户个人系统，无"人员分配"字段与协作功能**。「布置给相关人员」在本系统中&#x4EE5;**「项目归属 + ★ 执行清单 + 描述/备注」**&#x627F;载（结构布置 + 执行布置）；真正的人员协作/指派建议作为产品演进方向（见文末附录 A），验收时按现有语义执行。

### FocusCard

**无**（项目页不渲染 FocusCard）。

### 衔接与数据流转

- 挂树 → `parentId` 写入；★ → `star=true`。
- **数据流向下一环节**：★ 任务进入 Plan 收集箱（收集箱只放行 ★ 任务，V3 设计）；挂树后任务在 Plan/Today 的归属链（ancestors）完整可查。

## 4. 环节四 ｜ 08:30 开工前 · Plan 拖拽排期

| 维度        | 内容                                                                           |
| --------- | ---------------------------------------------------------------------------- |
| **时间点**   | 08:30（5-10 分钟）                                                               |
| **页面/模块** | `Plan 蓝图·规划`                                                                 |
| **核心功能点** | 周视图（周切换/聚焦模式）、**收集箱拖拽排期**、时间块拖动改期、详情浮层（改时间/追加子任务/移除排期/开始执行）、续排建议、凌晨折叠区、计划健康度 |

### 操作步骤

1. 进入「蓝图」→ 周视图展示本周；「本周截止」条展示未来 7 天有截止任务。
2. **拖拽排期**：从底部「收集箱」（★ 任务待安排池）拖任务块到目标天列的目标时段（时间轴 08:00-22:00）→ 落库（apply-decision 时间服务，唯一合法改时间入口）。
3. **调整已有排期**：拖动周视图内已排时间块到新时段；或点击任务块打开详情浮层 → 修改时间。
4. 追加子任务：详情浮层「＋ 追加子任务」。
5. 移除排期：详情浮层「移除/删除排期」（任务保留在收集箱）。
6. 未完成任务的「续排建议」条：展开「未完成任务 · 明天继续」→ 对某项点「复制到明天」→ 明天同时间段生成排期。
7. 查看「计划健康度」折叠条（负荷分析）与凌晨折叠区（22:00-02:00 跨夜任务）。

### FocusCard

**无**（但排期结果直接决定 Today 的卡片触发：**有排期且无子任务 → 时间型卡**；排期进入今日路线）。

### 衔接与数据流转

- 拖拽/改期 → `Schedule` 落库（scheduledStart/End，source=user）；移除 → 软删排期。
- **数据流向下一环节**：今天的排期构成 Today「今日路线」时间线（getTodayTimeline：今天有排期的任务按时间升序）；currentTask 优先取「进行中」任务，其次「当前时段排期任务」（已过滤终态），否则 mustDo 兜底。

## 5. 环节五 ｜ 09:00-09:50 · FocusCard ① 清单型（做产品/项目）

| 维度       | 内容                                                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **触发场景** | 任务**有子任务（执行清单）**&#x6210;为当前任务（如「完成产品需求评审文档」拆了 3 个子项）                                                                                          |
| **展示位置** | Today 主区左栏 FocusCard（视口 ≥860px 两栏布局，动机行横跨顶部）                                                                                                  |
| **卡片内容** | A 动机行（purpose，紫色）；主卡：标题/类型标签「清单型」/所属项目链；执行清单（子项勾选 + 「＋」新增）；D 区操作按钮；状态标签「未出发/进行中/已完成」                                                          |
| **支持操作** | ① 出发（记 departureAt，进入计时）② 勾选子项（子任务 complete 落库，进度实时刷新）③ 「＋」新增子项（inline 输入回车/确定）④ 「该项完成」→ 补记时长弹窗（默认=现在−出发，可改）→ 确定 ⑤ 「跳过后一项」⑥ 「暂停」（选原因）⑦ 「明天继续」 |

### 操作步骤

1. Today 主卡即为「完成产品需求评审文档」（清单型）→ 点「出发」。
2. 卡片显示「从 09:00 出发」，D 区出现「该项完成 / 跳过后一项」；执行清单 0/3 已完成。
3. 逐项勾选：完成「评审文档初稿」→ 点清单项勾选框 → 该项打勾（1/3）；卡上「已完成 1/3 · 总耗时 X 分钟」实时更新。
4. 中途发现缺项 → 「＋」新增「补充验收清单」子项（乐观更新）。
5. 完成全部 3 项 → 「该项完成」→ 补记时长弹窗（默认值 = 现在 − 出发时刻）→ 点「确定」→ 卡片转「已完成 ✓」。
6. （备选）若被打断 → 「暂停」选原因（记录 UserObservation）→ 卡片回「未出发」。

### 衔接与数据流转

- 出发 → `Task.status=in_progress` + `departureAt`；勾选 → 子任务 completed + completedAt；完成 → 父任务 completed + 补记 TimeLog（manual，先建日志再算 actualMinutes）+ 当日摘要强制刷新。
- **数据流向**：完成 → Projects 归档区 + 树行「✓ 完成」；Review 本周统计 +1；Plan 周历保留历史块。

## 6. 环节六 ｜ 10:00-10:50 · FocusCard ② 学习型（学书本知识）

| 维度       | 内容                                                                     |
| -------- | ---------------------------------------------------------------------- |
| **触发场景** | 任务**无子任务且无排期**（如「背考研英语单词 50 个」）→ 自动推断为学习型                              |
| **展示位置** | Today 主区（学习型卡片宽度策略 360px，可收窄）                                          |
| **卡片内容** | 动机行；类型标签「学习型」；「知识点」列表（子任务映射为知识点）；「已学 N/M 节 · 总耗时 X 分钟」；D 区「该项完成/跳过后一项」 |
| **支持操作** | 勾选知识点（**可逆**：再点取消勾选）、＋新增知识点、出发/该项完成/跳过/暂停/明天继续——与清单型同构，区别在"可逆勾选"语义与标签  |

### 操作步骤

1. 轮播/路线切换至「背考研英语单词」学习卡 → 「出发」。
2. 学一节勾一节：点「list 1 高频词」→ 勾选（已学 1/4）；学完发现没记住 → 再点取消（可逆，符合学习场景）。
3. 「＋」新增知识点「真题长难句 5 句」。
4. 学完 → 「该项完成」→ 补记 → 完成。

### 衔接与数据流转

- 同清单型（勾选落子任务状态、完成落父任务 + TimeLog + 摘要刷新）；差异仅在**类型标签与可逆交互语义**。
- **数据流向**：完成 → 归档 + 统计；未完成的排期任务（若后续在 Plan 排期）→ 自动升级为时间型呈现（见环节七）。

## 7. 环节七 ｜ 11:00-12:00 · FocusCard ③ 时间型（固定时间，到点自动完成）

| 维度       | 内容                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| **触发场景** | 任务**有排期且无子任务**（如「组会 11:00-12:00」）→ 时间型（timer）                                                                 |
| **展示位置** | Today 主区（360px 可收窄）；今日路线中该时段高亮 isCurrent                                                                      |
| **卡片内容** | 固定时间区间（scheduledStart-End）、「预计 X 分钟」、类型标签「固定时间」、倒计时/到点提示、D 区「完成」（timer 主按钮为「完成」而非「出发」）                        |
| **支持操作** | ① 到点自动完成（**惰性结算**：打开 Today 页面时补算过期 scheduled，自动完成，detail='auto'，无 cron）② 提前结束：手动点「完成」③ 「明天继续」复制到明天同时间 ④ 暂停/跳过 |

### 操作步骤

1. 11:00 组会卡自动出现（currentTask 命中当前时段排期）→ 无「出发」按钮，主按钮即「完成」。
2. 11:45 提前散会 → 手动点「完成」→ 补记时长（默认按排期时长）→ 确定。
3. （备选验证）若一直不操作，12:00 后**重新打开/刷新 Today** → 该任务被惰性结算自动完成（无需手动），统计正常计入。

### 衔接与数据流转

- 手动完成：同清单型完成链路；自动完成：`views/today` 打开时 `lazySettleExpiredScheduled` 幂等补算（status=completed，TimeLog detail='auto'）。
- **数据流向**：完成 → 归档 + 统计 + 摘要刷新；「明天继续」→ 明天同时间段新增排期（Today 卡片次级按钮）。

## 8. 环节八 ｜ 12:30 午间 · Plan 拖拽改期（冲突调整）

| 维度        | 内容                                           |
| --------- | -------------------------------------------- |
| **时间点**   | 12:30（2-3 分钟）                                |
| **页面/模块** | `Plan 蓝图·规划`                                 |
| **核心功能点** | 时间块拖动改期（带 scheduleId 精确替换）、详情浮层改时间、移除排期、续排建议 |

### 操作步骤

1. 下午任务（如「健身 45 分钟」积累卡排期 15:00）与会议冲突 → 进入 Plan。
2. 直接拖动「健身」时间块到 18:00 时段（或打开详情浮层改时间）→ 保存即生效（apply-decision）。
3. 被顶掉的时段任务自动显示冲突/健康度变化（计划健康度条）。

### 衔接与数据流转

- 拖动 → Schedule 更新（同任务同日只保留最新一条，防重复块）；**下一环节** Today 的今日路线与 currentTask 随新时间刷新。

## 9. 环节九 ｜ 15:00-15:30 · FocusCard ④ 积累型（每日打卡/频次坚持）

| 维度       | 内容                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| **触发场景** | 任务为**积累型**（Inbox「设为每天」或创建时 accumulate）→ accum-daily（每日）/ accum-weekly（频次）                                    |
| **展示位置** | Today 主区；Projects 习惯区（打卡唯一入口）同步显示                                                                            |
| **卡片内容** | 类型标签「积累·每日/积累·频次」；「连续 N 天 · 本周已打卡 M 次」；月小日历点阵（周一开头 7 列，打卡日高亮）；今日动作清单（accum-weekly 有「今日动作」列表）；D 区「出发→打卡→打卡完成」 |
| **支持操作** | ① 出发 ② 「打卡」→ CheckinModal（可填打卡内容，存 TimeLog.detail）→「打卡完成」③ 连续天数/点阵实时更新 ④ 暂停/跳过/明天继续                          |

### 操作步骤

1. 18:00（已改期）健身卡出现 → 「出发」→ 卡片转 going。
2. 健身结束 → 「打卡」→ 打卡弹窗输入「卧推 5 组 + 跑步 3km」（可空）→ 「打卡完成」。
3. 卡片显示「已打卡 1 次 · 连续 1 天」，月历点阵今日点亮；Projects 习惯区同步「已打卡 ✓」+ 树行金色状态点「今日已打卡」。
4. 次日再练 → 连续 2 天；中断一天 → 连续重新计数（"中断不算断"）。

### 衔接与数据流转

- 打卡 → `TimeLog type=checkin`（durationSeconds 计入当日专注）+ `UserObservation`（坚持行为学习闭环）+ 当日摘要刷新。
- **数据流向**：Projects 习惯区 streak（current/longest/last30）经 `/api/tasks/:id/streak` 实时读取；Review 周报统计打卡行为。

## 10. 环节十 ｜ 21:00 晚间 · 复盘与明日铺垫

| 维度        | 内容                                                            |
| --------- | ------------------------------------------------------------- |
| **时间点**   | 21:00（10 分钟）                                                  |
| **页面/模块** | `Review 复盘·学习` → `Plan`（续排）                                   |
| **核心功能点** | 本周/本月切换、核心指标（完成数/专注分钟/完成率）、产出日记按天分组、本周洞察、主题投入（周环比）、应用建议写入长期记忆 |

### 操作步骤

1. 进入「复盘」→ 查看本周完成 N 项、专注 M 分钟、完成率。
2. 向下滚动：产出日记（按天分组的时间记录）、本周洞察（AI 行为分析）、主题投入（本周各主题排期占比 + 周环比箭头）。
3. 有建议时点「应用」→ 写入长期记忆（agent memory）。
4. 切到 Plan → 「未完成任务 · 明天继续」→ 对没做完的任务点「复制到明天」。

### 衔接与数据流转

- 复盘数据源：daily_summaries（打开 Today 自动生成 + complete/checkin 后强制刷新）+ 行为分析（异步 pipeline）。
- **数据流向**：续排 → 明天新增排期 → 明日 Today 路线自动出现；长期记忆 → 影响后续 AI 建议。

## 11. 环节衔接总览（数据流转图）

```
Inbox(录入/调整) ──确认──▶ Task 落库(身份/结构/时间元数据)
      │
      ▼
Projects(归类/★) ──parentId/star──▶ 收集箱候选 + 归属链
      │
      ▼
Plan(拖拽排期) ──Schedule──▶ 今日路线 + 本周截止 + 续排
      │
      ▼
Today(四款 FocusCard 执行)
  ├─ 清单型：出发→勾选→完成(补记) ──▶ TimeLog + actualMinutes + completedAt
  ├─ 学习型：出发→可逆勾选→完成
  ├─ 时间型：到点惰性结算 / 手动完成
  └─ 积累型：出发→打卡(detail) ──▶ TimeLog(checkin) + streak
      │
      ▼
Projects(归档/习惯区) ──completed──▶ 归档区 + 树行状态
      │
      ▼
Review(复盘) ◀── daily_summaries(complete/checkin 后刷新) + 行为分析
      │
      ▼
Plan 续排(未完成→明天) ──▶ 明日 Today 路线
```
