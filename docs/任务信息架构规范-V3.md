## 1. 五层信息模型

> 核心原则：**一个信息只有一个「家」，在哪生，就在哪管。** 任何字段只有一个编辑入口。

### 1.1 分层总览

| 层 | 管理页面 | 谁来填 | 可否编辑 |
|----|---------|--------|---------|
| 身份层 | Inbox | AI 解析 + 人工确认（**全系统唯一确认点**） | 创建时定，档案面板可改 |
| 结构层 | Project | 人工拖拽/键盘（AI 不碰） | 随时改 |
| 时间层 | Plan | 人工拖拽 + AI 建议（必须确认） | 随时改 |
| 执行层 | Today | 执行时自动产生 | 执行时操作 |
| AI 增强层 | 无 | AI 全自动 | 只读，不进卡片 |

### 1.2 分层字段表

**身份层**：title（AI 提取+确认）/ category 领域（AI 猜+确认）/ theme 主题（AI 猜+确认）/ taskType 计划状态（inbox|planned|scheduled）/ estimatedMinutes / source（user|ai）

**结构层**：parentId（项目树归属）/ level（project|phase|task）/ accumulate（布尔）/ children（执行清单）/ description（备注）/ sortOrder

**时间层**：Schedule.scheduledStart/scheduledEnd（唯一时间源）/ deadline / 续排（continue_tomorrow）

**执行层**：status（not_started|in_progress|completed|delayed|snoozed|cancelled）/ TimeLog（focus|checkin）/ children 勾选态 / completedAt

**AI 增强层**：complexity / riskLevel / dependencies / scheduleAdvice（planner 消费；任何 UI 禁止直接展示，档案面板 AI 区块折叠只读除外）

### 1.3 收银台模式（读聚合、写分散）

- **读**：任务档案面板聚合五层（见 §5.2）
- **写**：身份→Inbox 表单/档案面板、结构→Project、时间→Plan；**禁止**两个页面改同一字段

## 2. 四维分类模型

> 核心原则：**四个维度各管各的，永不合并、永不互相替换。**

| 维度 | 回答 | 数量 | 谁定 | 决定什么 |
|------|------|------|------|---------|
| 形态 | 怎么显示 | 固定 4 种 | 数据推断（不落库） | 卡片长相 |
| 领域 | 属于什么生活 | 7 类封顶 | Inbox 确认 | 颜色基调 |
| 主题 | 为了什么目标 | 自由扩展 | 标签随手打 | 角标色 |
| 项目 | 在哪棵树 | 任意深度 | Project 页 | 归属链 |

### 2.1 形态（不落库，前端推断）

| 形态 | 判定 | 例子 |
|------|------|------|
| 计时型 | 有排期、无子任务、非积累 | 上课/开会 |
| 清单型 | 有子任务（children 非空） | 画原理图 |
| 学习型 | 无排期、无子任务、非积累 | 精读论文 |
| 积累型 | accumulate=true（每日/频次） | 背单词/健身 |

### 2.2 领域（7 类封顶，**不再增加**）

> 配色按 2026-08-02 预览验收决策更新（决策 D16：暖色纪律——暖色只留给主题，低频领域低调化）

| key | 中文 | border | bg |
|-----|------|--------|-----|
| course | 课程 | #475569 | #E2E8F0 |
| learning | 学习成长 | #3B82F6 | #DBEAFE |
| practice | 专业实践 | #7C3AED | #EDE9FE |
| health | 健康生活 | #16A34A | #F0FDF4 |
| life | 个人事务 | #CA8A04 | #FEFCE8 |
| external | 社团/外部 | #92400E | #FEF3C7 |
| other | 未分类（兜底） | #94A3B8 | #F8FAFC |

**配色原则（暖色纪律，决策 D16）**：
- 突出最重要两领域：learning 蓝 / practice 紫（加深底色 + 深竖条）
- 中性色（灰蓝/灰）做背景不抢戏；暖色只留给主题（考研橙 #F97316 / 竞赛粉 #DB2777）
- external 深棕褐 #92400E（低调不抢戏）；health 保持原绿（否决黄绿方案）
- 周历任务块统一加 0.5px 细边框（rgba(15,23,42,.07)），紫块在淡紫时段背景上也有边界

> 决策 D8：**competition 已移除**，存量迁移为 practice + theme:竞赛。新增"目标"诉求一律走主题，不碰领域。

### 2.3 主题（自由扩展，独立字段）

- 存储：`Task.theme String?` + `@@index([userId, theme])`（决策 D9）
- 预设 chips（决策 D15，**替代 D11**）：**考研 / 竞赛 / 身材** + 自定义（选颜色 + 输名称 ≤20 字符）
- 配色（决策 D15/D16）：竞赛 #DB2777 / 考研 #F97316 / 身材 #0D9488；自定义主题 = 10 色色板选色
- 显示：Plan 周历标题旁主题徽章（深字浅底 + 色点，对比度 ≥4.5:1）、卡片小徽章、档案面板
- 解析：AI parser 推断（拿不准留空，不强猜）
- **暖色纪律**：暖色（橙/粉/琥珀）只留给主题角标；领域色一律冷色/中性

### 2.4 项目

任意深度树（项目→阶段→★任务→执行项），parentId 自关联，Project 页管理。
考研落位示例：考研（项目）› 数学/英语（阶段）› 「考研数学第三章」（★任务）› 执行项。

### 2.5 四维速查

```
「考研数学」= 清单型 + 学习(蓝) + 主题考研(橙) + 项目考研›数学
「电赛调试」= 计时型 + 实践(紫) + 主题竞赛(红) + 项目电赛
「背单词」  = 积累·每日 + 学习(蓝) + 主题考研(橙) + 项目考研›英语
```

## 3. 产品宪法决策（7 个产品问题 → 设计决策）

> 来源：2026-08-02 产品定位审查。以下决策对开发是**硬约束**。

| # | 决策 | 对开发的要求 |
|---|------|-------------|
| D1 | **产品定位 = 个人成长系统** | 功能取舍对照"成长闭环"；不做泛用功能 |
| D2 | **北极星指标**：周完成率/采纳率/堆积率 | Review 加「指标卡」区块（stats API，零新后端） |
| D3 | **主题复盘本期实施** | stats API 加 `themeBreakdown`；Review 战报「主题投入」区块。**口径（决策 D17）**：按本周排期任务数聚合（主题 N 项 · 占比 % · 主攻/待加强标签），非时长；数据来自 prisma/dev.db 真实任务 |
| D4 | **提醒红线**：只服务承诺兑现，可一键关 | 积累打卡提醒/截止前 1 天提醒可用；禁止泛通知。网站形态无推送权限，天然克制 |
| D5 | **数据主权**：导出带 schemaVersion | settings 导出 JSON 加 `schemaVersion` 字段 + 迁移映射表 |
| D6 | **卡片三层一致**：身份→时间→状态 | 所有卡片组件（Today/Plan/Project/收集箱/搜索）必须三层，其余进详情；禁止自创样式 |
| D7 | **AI 透明化边界**：结论进主流程、推理进设置 | 主流程 AI 只给"结论+可应用动作"；Trust Score/记忆/决策日志只在 Settings |

## 4. 后端开发契约

### 4.1 数据库最终 schema（Task 模型）

```prisma
model Task {
  id               String    @id @default(uuid())
  userId           String
  parentId         String?
  title            String
  description      String?
  taskType         String    @default("inbox")   // 计划状态：inbox|planned|scheduled
  status           String    @default("not_started")
  deadline         DateTime?
  importance       Int       @default(3)          // temperature 已删除
  estimatedMinutes Int?
  actualMinutes    Int       @default(0)
  tags             String?                        // 仅用户自由标签（无系统前缀）
  snoozeUntil      DateTime?
  sortOrder        Int       @default(0)
  completedAt      DateTime?
  createdAt        DateTime  @default(now())
  updatedAt        DateTime  @updatedAt
  category         String?                        // 领域：7 类（无 competition）
  theme            String?                        // 主题：自由文本单选
  complexity       String?                        // AI 增强（planner 消费）
  riskLevel        String?
  dependencies     String?
  scheduleAdvice   String?
  phaseOrder       Int       @default(0)
  postponedCount   Int       @default(0)
  source           String    @default("user")
  level            String?   @default("task")     // project|phase|task
  accumulate       Boolean   @default(false)
  // 已删除字段：temperature / startTime / endTime / cognitiveLoad / schedulingHint
  // 索引：现有全部保留 + @@index([userId, theme])
}
```

### 4.2 迁移脚本（一次性）

1. `prisma migrate dev` 应用变更
2. `category='competition'` → `category='practice'` + `theme='竞赛'`
3. 标题含「考研/数学/英语/政治/专业课」的 learning 任务 → `theme='考研'`
4. 剥离 tags 中 `domain:*` / `theme:*` / `important:*` 前缀
5. 校验：无 competition 残留、无系统前缀、无死字段写入

### 4.3 服务层改动

| 文件 | 改动 |
|------|------|
| `src/lib/plan/colors.ts` | DOMAINS 移除 competition；新增 THEMES 表（§2.3 配色）；新增 `resolveTheme(tags,title,category?)`；TAG_MAP 移除"考研/英语"→learning；删除 `buildTagsForDomain` |
| `src/lib/ai/parser.ts` | ParsedTask 加 `theme`；prompt 加主题判断（拿不准留空）；fallback 加主题关键词 |
| `src/lib/task-builder.ts` | theme 透传建树 |
| `src/lib/ai/confirm-service.ts` | theme 落库；category 白名单 7 类；时间只走 Schedule |
| 新增 `src/lib/task/theme.ts` | getTheme / themeColor / normalizeThemeInput |
| `src/lib/ai/planner.ts` | prompt 注入 theme 分布（可选增强） |

### 4.4 API 契约

**新增**：
- `GET /api/tasks/search?q=` → `{ results: [{id,title,category,theme,status,parentTitle,scheduledStart?}] }`（标题/标签/归属链 contains；空 q 400）

**修改**：
- `POST /api/tasks`：+theme；移除 temperature/startTime/endTime；category 白名单 7 类
- `PUT /api/tasks/[id]`：白名单 +theme；移除死字段写入
- `POST /api/inbox/analyze`：items +theme
- `GET /api/views/today`：currentTask +theme/themeColor
- `GET /api/views/week-calendar`：scheduledTasks/plannedTasks +theme；图例 +themes
- `GET /api/tasks/[id]`：档案面板聚合 +theme/+ancestors/+schedules/+accumStats/+aiFields(只读)
- `GET /api/views/stats`：+`themeBreakdown`（决策 D3）；+`?theme=` 过滤

**删除**（确认零引用）：`/api/ai/ingest`、`/api/ai/today-suggest`、`/api/plan/edit-schedule`、`/api/plan/delete-schedule`、`/api/views/week`。**保留** `/api/plan/repeat`（积累型依赖）。

### 4.5 AI 链路与反馈回流

- buildAgentContext：注入 theme 分布（"用户当前主题：考研×N"）
- pattern-mining：新增 Rule10「主题时段偏好」（可选，不阻塞）
- **领域/主题修改回流**：Inbox 确认时「AI 推断值 ≠ 用户最终值」→ 写 `AgentFeedback(userResponse='modify', modifiedField='category'|'theme', originalValue, userValue, taskId)` → 计入 computeTrustScore + memory-learning
- 红线：AI 增强字段（complexity 等）任何 UI 禁止直接展示

## 5. 前端开发契约

### 5.1 卡片三层规则（决策 D6，强制）

所有任务卡片：**身份（标题+形态徽章+领域色）→ 时间（排期/截止梯度）→ 状态（进度/打卡）**，其余进详情。

### 5.2 任务档案面板（核心新组件）

- 打开：任意页面点任务 / 搜索结果；形态：宽面板 ≈560px，五区块
- 身份：面板内编辑（PUT tasks/[id]）；结构：去 Project 定位；时间：去 Plan 定位；执行/AI：只读
- 数据源：`GET /api/tasks/[id]`（§4.4 扩展）；基础：TaskDetailPopover 升级

### 5.3 全局搜索

顶部导航搜索框 → `GET /api/tasks/search` → 结果列表 → 点击开档案面板。

### 5.4 各页面改动

| 页面 | 改动 |
|------|------|
| Inbox | 确认表单 +主题 chips（**3 预设：考研/竞赛/身材** + 自定义选色输名，决策 D15）；分类器 7 类；「专业实践」旁小字"（含竞赛）"（决策 D10）；主题引导文案"记录但不背目标，想追踪可自定义" |
| Plan | 周历块领域底色+标题旁主题徽章（色点+文字，块高<40px 只显色点）；图例+主题；TaskDetailPopover +主题编辑 |
| Today | Focus Card +主题小徽章（克制） |
| Project | 树节点主题徽章（可选） |
| Review | 分类 7 类自动生效；**指标卡**（D2，顶部 8px 色条+名称前圆点）；**主题投入区块**（D3/D17，按任务数）；关键词统计简化（无系统前缀） |
| Settings | 导出 +schemaVersion（D5）；AI 记忆仪表盘不动 |

### 5.5 文案统一

| 旧 | 新 |
|----|----|
| 任务类型 | **计划状态**（inbox=想法/planned=截止日/scheduled=时间块） |
| 卡片类型 | **卡片形态**（计时/清单/学习/积累） |
| 竞赛冲刺（分类） | 专业实践 + 竞赛主题 |
