# 五页面布局重排方案（前端执行稿）

> 日期：2026-08-03 | 性质：前端布局重排需求（**不动数据、不动接口、不动功能逻辑**）
> 原则：**每个页面只保留一条「决策链」**——核心行动首屏、辅助分析靠后、自我汇报沉底折叠
> 本次范围：Today / Plan / Review 三页重排 + 跨页顺手项。Inbox / Project 不改（已达标）。

---

## 0. 三区原则（所有页面通用）

| 区 | 放什么 | 位置 |
|----|--------|------|
| 核心行动区 | 用户打开这页要做的那个动作 | 首屏第一眼 |
| 辅助分析区 | 帮助决策但非动作本身 | 核心区之后 |
| 沉底折叠区 | 自我汇报/低频信息 | 页面底部折叠条 |

---

## 1. Today · 今日驾驶舱（默认落地页）

### 现状
页头 → Focus Card → 状态仪表盘 → 今日路线 | AI 助手（双栏）

### 问题
状态仪表盘（精力/专注/情绪/压力 + 调整）横插在 Focus Card 与今日路线之间，腰斩决策链——它是"向 AI 汇报"，不是"帮用户决策"。

### 重排后
```
页头（问候语 + 日期 + 完成数/专注分钟徽章）  [不变]
→ Focus Card V2（核心，不变）
→ 今日路线 | AI 助手（双栏 grid，保持不变）
→ 今日状态（沉底折叠条）
```

### 折叠条规格（新交互）
- 标题：「今日状态」+ 展开箭头；**默认收起**
- 展开后：精力/专注/情绪/压力 4 项展示 + 内联「调整」编辑区（现有 StatusBar 组件整体移入，逻辑不动）
- 只有一条：今天状态有变化时才需要展开——低频交互放折叠

---

## 2. Plan · 规划

### 现状
健康度条 → 本周截止 → 周历 → 收集箱

### 问题
① 健康度（分析结论）占首屏；② 本周截止与周历块上的"X日截止"红标重复；③ 四个大区块堆叠无主次

### 重排后（采纳用户方案：截止比收集箱紧急，更靠上）
```
本周截止（顶部折叠条，默认收起，只露 badge「N 个截止」）
→ 周历甘特图（核心，永远全展开）
→ 收集箱（贴周历，拖拽源）
→ 计划健康度（沉底折叠条）
```

### 折叠条规格
- 本周截止：标题 + 计数 badge；**默认收起**；展开显示现有 DeadlineRow 卡片（逻辑不动）
- 计划健康度：标题「计划健康度」+ 展开箭头；**默认收起**；展开显示健康分进度条 + 首条问题（现有逻辑不动）

---

## 3. Review · 复盘（手术重点）

### 现状顺序
指标卡 → 主题投入 → 战报 → 产出日记 → 本周洞察 → 下周建议

### 问题
① 叙事顺序反了：战报（"这周怎么样"）被压到第 3 位；② 本周洞察与战报重复；③ 指标卡与战报 3 格统计边界不清；④ 主题投入缺趋势

### 重排后
```
战报（故事：周标题 + 主色 + 发现条 + 本周战果）
→ 指标卡（健康仪表 4 格）
→ 主题投入（+周环比趋势，见下）
→ 产出日记（明细证据）
→ 本周洞察（精简版）
→ 下周可以试试（行动）
```

### 具体改动（3 项）

**① 战报卡：删「连续天数」**
- 战报底部 3 格：完成任务 / 专注时长 / ~~连续天数~~ → 保留前两项（战果总量）
- 理由：连续天数与指标卡「打卡保持率」重复

**② 本周洞察：删 2 保留 2**
- 删：分类时间占比条（战报"主色+发现条"已表达）、最认真时段（同上）
- 保留：任务时段偏好（"更喜欢在下午完成"）、打断注意
- 理由：战报是"结论"，洞察不该重复列同一组数字

**③ 主题投入：加周环比趋势**
- 每行主题加「较上周」：`考研 25h · 占 60% · ↑12%`（上升绿/下降红/持平灰）
- 数据：stats API 需返回上周 themeBreakdown 对比（**后端小改**：`themeBreakdown` 增加 prev 字段，或前端调两次 range=week / range=prev_week；若后端未就绪，前端先留空位显示"—"）
- 这是决策 D3 的核心价值：主题=目标，趋势才知道是进步还是退步

## 7. 二次修订（2026-08-03 下午 · 用户反馈后）

> 前置：§1-§6 已确认方案（Today 沉底折叠 / Plan 折叠条 / Review 删重）**继续有效**。本节是在其之上的布局引擎升级，两节冲突处以本节为准。

### 7.1 Today：弹性方案「简单/复杂双态」定稿（2026-08-03 17:55 · UI 设计师出稿 + 产品审核通过）

> **修订链**：初版「左主右辅」被否决（三层嵌套）→ 二版「宽度集中」定方向 → **UI 设计师出稿《UI示例/Today-弹性方案-类型全览-2026-08-03.html》方案 B「弹性让位」，产品审核通过，本节为最终定稿**。

**问题根因（代码实证）**：Today 是宽页面（ContentContainer `WIDE_SIDE=1160px` / `WIDE_TOP=1280px`，而 Review 只有 720px）。Focus Card 在 1160px 全宽下内部再分 0.72/1.28 两栏 → 卡片被撑得极宽，视觉奇怪；且主卡字小（标题 17px），重点不突出。

**方案 B「弹性让位」——卡片内容多就"长大"，内容少就"缩小"**：

| 项 | 简单态 | 复杂态 |
|----|--------|--------|
| 宽度 | **760px 居中** | **880px 居中**（200ms 宽度过渡） |
| 首屏 | 三块一屏全见：主卡 + 路线\|AI + 状态条 | 只放问候语 + 主卡；路线\|AI **完整沉底**（滚动即见，信息不丢）；状态条继续折叠 |
| 覆盖场景 | 固定时间（无清单）、积累·每日（无清单）、积累·频次（≤3 动作）、清单型·仅 1 项 | 清单型 10 项、积累·频次 ≥5 动作 |
| 视觉基准 | `UI示例/Today-弹性方案-类型全览-2026-08-03.html`（5 场景全渲染，含判定规则） | 同左 |

**简单/复杂判定规则（不写死阈值）**：渲染后测量「问候语 + 主卡」实际总高度，≤ 一屏可用高度（约 560–600px）→ 简单态；超出 → 复杂态。0 条清单的时间型、3 动作的健身、10 项的原理图各自自动归位。

**保留不变**：纵向结构（主卡 → 路线\|AI → 状态折叠，无外层分栏）；Focus Card 内部左右栏（0.72/1.28）；memo 黄清单 + data-title 小标题；主题角标；暂停/补记/打卡弹窗逻辑。

**字号提升（用户明确要求："名称归属不能这么小"）**：

| 元素 | 现状 | 改为 |
|------|------|------|
| 任务标题（B 区 h3） | `text-[17px] font-bold` | **`text-[20px] font-bold`** |
| 所属项目（左栏） | `text-[13px] font-semibold` | **`text-[14px] font-semibold`** |
| 动机行（A 区） | `text-[11.5px]` | **`text-[12.5px]`**（可带主题 tag，如 考研/身材/竞赛） |
| 元信息（预计/已用/地点） | `text-[10px]` | 保持小字（角标语义，不抢戏） |

**AI 输入框上移（用户明确要求）**：
- 现状：输入框在 AiPanel **底部**（`border-t` 分隔的 flex 区）
- 改为：移到**紫色标题栏正下方**（面板内容区最顶部）——先输入/提问，再浏览建议列表
- 结构：`标题栏 → 输入框（+发送）→ AI 提示语 → 建议列表 → 回复气泡`

**视觉重点原则**：主卡是绝对主角（大字号 + 高密度）；路线/AI 是辅助（维持现字号，不放大）。

**移动端（<900px）**：`row2` 单栏、`fc-body` 纵向折叠（`fc-left` 去掉右边框改下边框），回退单栏堆叠。

### 7.2 Review：改为「上锚点 + 左证据右仪表」两栏

**问题**：6 区块单栏纵排，滚动太长。

**决策（产品定稿）**：

```
[ 战报（顶部全宽 · 故事锚点）            ]
[ 产出日记（左 65% · 主叙事+下周建议） | 指标卡 2×2 → 主题投入 → 本周洞察（右 35% · 仪表区 sticky） ]
```

**分栏依据**：
- **左列（主叙事）**：产出日记（证据，最长最重）+ 下周建议（行动承接叙事，放日记尾部）
- **右列（仪表区）**：指标卡（4 格改 `grid-cols-2` 2×2）→ 主题投入（含趋势）→ 本周洞察（精简版）；`sticky top` 跟随
- **顶部全宽**：战报（故事开头锚点，不拆栏）
- **移动端（<860px）**：回退单栏，顺序不变：战报 → 指标 → 主题 → 日记 → 洞察 → 建议

**实现要点**：
- 战报独立全宽；下方 `<div class="grid grid-cols-1 lg:grid-cols-[13fr_7fr] gap-4 items-start">`（约 65/35）
- 右列 `<div class="space-y-4 lg:sticky lg:top-4">`
- MetricCards 在右列内改 2×2（`grid-cols-1 sm:grid-cols-2`）
- 各区块组件本身零逻辑改动，只改容器和位置

### 7.3 Non-goals（二次修订补充）

- ❌ 不改 FocusCardV2 内部状态机 / 数据契约（只动外层容器 + 字号 + 输入框位置）
- ❌ 不动 Review 各区块的数据逻辑（只动容器分栏）
- ❌ 不做复杂卡的"右列压缩/隐藏"——sticky 跟随即可，不加状态切换
- ❌ 不引入新组件库 / 布局框架（纯 Tailwind grid + sticky）

### 7.4 验证（追加）

- 浏览器实测（≥860px）：Today 三块首屏全见；简单卡/复杂卡各看一遍；AI 输入框在面板头部；Review 双栏 + 右栏 sticky
- <860px 宽度下 Today/Review 均回退单栏、顺序正确
- tsc + vitest + build 不受影响
