## 二、本次修复 Bug 明细

### BUG-20260808-050：mustDo 兜底卡的子任务勾选失效（产品 Bug，主路径高优）

- **现象**：Today 学习型卡（mustDo 兜底，非 currentTask）勾选知识点子任务后，children 状态恒为未完成（20s poll 超时）；勾选按钮点击无效。
- **根因**：`toggleChildItem` 只从 `data.currentTask.children` 查找被点项。mustDo 兜底卡场景 `currentTask === null` → item 缺失 → `item?.done` 为 undefined → 误发 `reopen` 给未完成子任务（reopen 不改状态）→ 子任务永不变更。
- **修复方案**：
  1. 查找源扩大到四类卡片的 children：`currentTask + routeSelTask + mustDo + recommended`；
  2. `done` 判断兼容两种序列化：`{id,text,done}`（views/today 增强）与 `{id,title,status}`（GET /api/tasks/:id 原始）；
  3. 定义移动到 `routeSelTask` 声明之后（useCallback 依赖 [data, routeSelTask, load]）。
- **代码变更**：`src/app/(dashboard)/today/page.tsx` → `toggleChildItem`。
- **验证**：12-daily-flow 环节 7 勾选→取消→再勾（可逆）全通过；`1 passed (5.1m)`。

### BUG-20260808-052：planned 任务被拖拽排期后误判「固定时间」卡（产品 Bug，主路径高优）

- **现象**：11-fullflow-ui 环节 ⑤ 路线点击任务 A（无子任务 + 有排期）后，前置卡显示「固定时间 · 到点自动完成」（无「出发」按钮）→ 提前执行不可达。此前通过属「排期失败反而假绿」（A 无排期 → 学习型 → 出发）。
- **根因**：`toCardV2` 的 timer 判定为 `hasSchedule ? "timer"`——任何无子任务但有排期的任务都被判为「固定时间」。但惰性结算（到点自动完成）仅对 `taskType=scheduled` 生效，用户手动拖拽排期的 planned 任务不会自动完成，显示「到点自动完成」语义错误且交互错乱。
- **修复方案**：timer 判定收窄为 `hasSchedule && taskType === "scheduled"`；planned+排期+无子任务 → learning 卡（有「出发」按钮，可提前执行计时）。
- **代码变更**：`src/app/(dashboard)/today/page.tsx` → `toCardV2`（type 判定）。
- **验证**：11-fullflow-ui 定向重跑通过；12-daily-flow 环节 8（组会 scheduled→timer）不受影响仍通过。

### 脚本层调整（非产品 Bug，测试稳定性）

- **12-daily-flow 环节 7**：勾选后移除 `page.reload()`——complete fetch（Neon 慢 3-7s）未落库即 reload 会中断请求，子任务状态不更新导致 poll 必失败（竞态）。BUG-050 修复后 `toggleChildItem` 自带 `load()` 刷新，无需 reload。
- **12-daily-flow 环节 6**：积累卡打卡后补「暂停」恢复 not_started——C 出发后 in_progress（+25 分 → 57 > D 的 35）会抢占 mustDo[0]，阻断学习卡可达性。
- **12-daily-flow 环节 7**：进入前补 `gotoNav(today)`（环节 6 末尾在 Projects 验证习惯区，reload 不回 Today）。
- **12-daily-flow 环节 8**：E（planned 组会，非 scheduled）由「时间型 timer 完成」改为「learning 卡 出发→该项完成→补记」——与 BUG-052 修复后的正确语义对齐；固定时间卡语义由环节 9 F2（scheduled 惰性结算）覆盖。
- **11-fullflow-ui 环节 ⑥-8**：搜索定位由 `text=${titleA}`（误匹配主卡 heading，点不到搜索结果）改为「未 」前缀 button 精确匹配。
