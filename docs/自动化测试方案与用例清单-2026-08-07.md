## 一、测试架构

```
tests/e2e/
├── playwright.config.ts       # 配置：串行执行(workers=1)、webServer 复用、storageState、reporter
├── global-setup.ts            # 全局前置：注册+登录"主测试用户"（时间戳邮箱，每次运行隔离）→ storageState
├── utils/
│   ├── helpers.ts             # 时间工具(localDateStr/dateOffset/nowHM…) + UI 辅助(导航/拖拽/toast)
│   └── api.ts                 # API 数据工厂：建任务/排期/打卡/状态操作/断言数据源（遵守产品红线）
├── modules/                   # 10 个模块脚本（按文件名 01→10 串行执行）
│   ├── 01-auth.spec.ts        # 认证
│   ├── 02-inbox.spec.ts       # 收件箱
│   ├── 03-plan.spec.ts        # 规划页
│   ├── 04-today.spec.ts       # 执行页
│   ├── 05-review.spec.ts      # 复盘页
│   ├── 06-projects.spec.ts    # 项目页
│   ├── 07-settings.spec.ts    # 设置页
│   ├── 08-search-archive.spec.ts # 全局搜索 + 档案面板
│   ├── 09-linkage.spec.ts     # 跨页面联动（重点）
│   └── 10-account.spec.ts     # 账户生命周期（独立临时用户）
└── run-report.mjs             # JSON 结果 → Markdown 报告（用例名/状态/失败原因/耗时）
```

### 关键设计

| 设计点 | 说明 |
|---|---|
| **统一入口** | `npm run test:e2e` → `playwright test -c tests/e2e/playwright.config.ts` |
| **按序执行** | `workers: 1 + fullyParallel: false`，模块文件按 01→10 编号顺序执行，数据依赖安全 |
| **数据隔离** | global-setup 每次运行注册**新用户**（`e2e-main-{timestamp}@test.local`），可重复运行不互相污染 |
| **真实用户操作** | 关键路径（创建/排期/打卡/完成/删除）走真实 UI 操作；数据准备用 API 工厂加速（同样遵守"排期走 apply-decision、状态走 action 白名单"红线） |
| **产品红线遵守** | 测试只通过 `POST /api/plan/apply-decision` 改时间、`POST /api/tasks/[id]/action` 改状态——测试本身即验证红线不被绕过 |
| **报告** | Playwright list + HTML + JSON 三路 reporter；`npm run test:e2e:report` 生成 Markdown 报告（用例名/状态/失败原因/耗时/通过率） |

### 运行流程

```bash
# 0. 首次初始化（安装浏览器二进制）
npm install               # 安装 @playwright/test（已写入 devDependencies）
npm run test:e2e:install  # 下载 Chromium

# 1. 启动 dev server（或复用已在 3000 端口运行的实例）
npm run dev

# 2. 全量执行（按序覆盖全部功能）
npm run test:e2e          # 前台执行（适合调试观察）

# 3. 后台执行（推荐日常回归：无头模式不抢焦点，中断自动重启）
npm run test:e2e:bg       # 日志 → e2e-results/run-<时间戳>.log
npm run test:e2e:stop     # 手动停止

# 4. 查看报告
npm run test:e2e:report   # Markdown：e2e-results/report.md
npm run test:e2e:open     # HTML 交互报告（含失败截图/视频/trace）
```

### 测试规范落实（2026-08-07 追加）

| 规范要求 | 落实方式 |
|---|---|
| **测试前自行注册新账号** | `global-setup.ts` 每次运行自动注册全新测试用户（`e2e-main-{timestamp}@test.local`，密码固定常量），登录态存 storageState 全量复用；01-auth / 10-account 模块另用独立临时用户，绝不污染主用户 |
| **信息细节校验（防类目误判）** | 类型/类目标签断言全部**严格化**，不允许"宽松兜底误判通过"：<br>· **T10 清单型任务**：有子任务必须渲染为清单型（子任务列表可见 + 勾选后 status=completed），若被误判为"学习"型则该用例失败<br>· R1 指标卡：完成率 + 堆积率双严格断言（不再"任意区块出现即可"）<br>· L3 树行"今日已打卡"状态点：严格断言（删除兜底 catch）<br>· G3 面板主题按钮：必须渲染，缺失即失败（不再 skip）<br>· S8 清理学习数据：API 回读记忆列表为空才算通过（不再仅 UI 文案）<br>· I9 草稿恢复：以输入框实际值为准（不再宽松匹配徽章）<br>· 仅对依赖外部条件（AI 未配置、规则未产出建议）的用例保留显式 `test.skip`（计入报告"跳过"列，**不算通过**） |
| **后台执行不抢焦点** | `npm run test:e2e:bg`：Chromium 强制无头（headless）运行 + `windowsHide` 不弹控制台窗口；日志落盘 `e2e-results/run-*.log`，随时可查 |
| **中断自动检测与重启** | `run-e2e.mjs` 内置：<br>· **中断判定**：退出码非正常（无完整 results.json / 信号终止 / spawn 失败）→ 视为外部干扰中断<br>· **自动重启**：默认最多重试 3 次（`E2E_MAX_RETRY` 可调），间隔 10s（`E2E_RETRY_DELAY`），每轮先清理旧结果防误判<br>· **正常结束判定**：有完整结果即停（含失败用例 → 提示查看报告，不盲目重跑）<br>· **停止方式**：`npm run test:e2e:stop`（pid 文件杀进程树）；运行器自身监听 SIGINT/SIGTERM 优雅退出 |

## 三、跨页面联动重点场景设计（L1 详述）

用户指定场景：**Project 页添加"执行清单" → Plan 规划排期 → Today 执行完成 → 数据验证**

```
① Projects（UI）
   新建项目(E2E联动项目) → 行尾 ＋ 新建子任务(E2E联动任务) → ★ 设为执行清单
   → 断言：star=true 落库（PUT /api/tasks/[id]）

② Plan（UI 拖拽，真实鼠标轨迹）
   收集箱拖 E2E联动任务 → 第 0 天列 10:00
   → 断言：schedules 非空（POST /api/plan/apply-decision 落库）

③ Today（UI）
   出发 → 该项完成 → 补记完成（时长弹窗）
   → 断言：status=completed（POST /api/tasks/[id]/action）

④ Projects（UI）
   归档区展开 → E2E联动任务可见（completed 落库后 tree 接口带出）

⑤ Review（API 断言）
   GET /api/views/stats?range=week → totalCompleted ≥ 1
```

**联动验证点**：①→②（未排期任务出现在 Plan 收集箱，靠 week-calendar 聚合）、②→③（今日排期进入 Focus Card/今日路线）、③→④（完成状态跨页同步，Projects 树/归档重取）、③→⑤（timeLog 驱动完成统计）。

## 四、断言与报告规范

1. **每条用例至少一个明确断言**：优先 UI 可见性断言 + 关键业务数据 API 断言双保险
2. **状态轮询**：跨页/异步数据用 `expect.poll`（默认 15s 超时），避免脆弱的固定 sleep
3. **失败留证**：失败自动保留 screenshot + video + trace（`retain-on-failure`），可 `npx playwright show-trace` 回放
4. **报告输出**：`e2e-results/report.md` 含每用例名称/状态/失败原因/耗时 + 汇总通过率；`playwright-report/` 为可视化 HTML
5. **跳过策略**：依赖 AI 配置/规则建议的用例在无前置条件时显式 `test.skip` 并注明原因（计入报告"跳过"列，不算失败）

## 五、失败调试与修复流程（执行阶段遵循）

当测试失败时（后续执行阶段）：

1. **定位**：读 `e2e-results/report.md` 失败原因 + 看 HTML 报告截图/视频/trace
2. **归类**：
   - 选择器失效（UI 文案/结构变动）→ 校准测试选择器
   - 数据前置缺失（用例间依赖）→ 补 API 数据工厂
   - **真实功能缺陷**（断言与产品契约冲突）→ 按 AGENTS.md 纪律修复代码：改 schema 走 prisma、改时间走 Schedule 服务、状态走 action 白名单
3. **修复**：`tsc --noEmit` + `npm test`（95 用例）保住既有质量线
4. **回归**：重跑失败模块 `npx playwright test -c tests/e2e/playwright.config.ts 04-today`，再全量 `npm run test:e2e` 直至全绿
5. **记录**：测试结果汇总文档（覆盖功能点、发现并修复的问题清单含原因分析、最终通过率）
