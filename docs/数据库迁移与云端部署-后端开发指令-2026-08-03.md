## 2. 阶段 A：代码改动（4 处）

### A1 `prisma/schema.prisma`

```diff
 datasource db {
-  provider = "sqlite"
+  provider = "postgresql"
   url      = env("DATABASE_URL")
 }

 generator client {
   provider = "prisma-client-js"
+  binaryTargets = ["native", "linux-openssl-3.0.x"]   // Vercel 构建保险
 }
```

### A2 `.env` / `.env.example`

```env
DATABASE_URL="postgresql://meridian:密码@localhost:5432/meridian"   # 本地测试先指本地 PG
AUTH_SECRET="（已有，保持）"
AUTH_TRUST_HOST="true"
```

### A3 `next.config.ts`（⚠️ 最容易踩坑）

```diff
 const nextConfig: NextConfig = {
   devIndicators: false,
   allowedDevOrigins: ["192.168.10.9"],
-  distDir: ".next-prod",    // Vercel 构建默认找 .next，推 GitHub 前必须注释
 };
```

### A4 其他

- 删除或忽略 `scripts/query_db.js`（硬编码 dev.db）
- `package.json` scripts 可选加：`"db:migrate": "prisma migrate deploy"`

## 3. 阶段 B：数据迁移（SQLite → Postgres）

### 方案 A（推荐）：pgloader 一键迁移

```bash
# 安装 pgloader（macOS: brew install pgloader / Linux: apt install pgloader）
pgloader prisma/dev.db "postgresql://meridian:密码@localhost:5432/meridian"
```

### 方案 B（备选）：Node 脚本

见主文档 §3 方案 B 骨架（node:sqlite 读 dev.db → JSON → pg 批量插入；依赖顺序 User 最先）。

> 主键全部是 UUID，无自增序列，数据直搬即可。**dev.db 永久保留作备份，不删除。**

## 5. 阶段 D：Vercel 部署准备

```
① Neon 免费库（neon.tech 注册 → Project → 拿连接串 postgresql://...?sslmode=require）
② 本地 PG 验证通过后，数据导入 Neon（pg_dump 导出 → psql 导入，或重新跑迁移）
③ .gitignore 确认包含：node_modules/ .next/ .next-prod/ .env prisma/dev.db
④ git init → commit → 推 GitHub（私有仓库）
⑤ Vercel 导入仓库（Framework 自动识别 Next.js）
⑥ Vercel 环境变量：DATABASE_URL（Neon 连接串）/ AUTH_SECRET / AUTH_TRUST_HOST=true
⑦ 部署 → https://xxx.vercel.app 可访问
```
