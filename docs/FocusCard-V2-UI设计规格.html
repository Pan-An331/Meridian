Focus Card V2 · UI 设计规格

产品逻辑已定稿 · 本规格面向 UI 设计师（视觉稿依据）· 2026-08-03 · 配套：总控 V2.0 / 信息架构 V3 / Today 设计稿（UI示例/Today的UI设计.html）

0. 设计原则（先读）

1
Today 是"启动台"不是执行场——用户打开 → 3 秒内明确"去做什么、为什么做"→ 放下网站去做（背单词开软件、健身去健身房、画图开 EDA）。卡片要"一眼读完就走"。
2
动机优先于信息——用户要的是"做这件事的理由"，不是"为什么安排在这个点"。理由行（purpose）是卡片第一视觉；排期理由只在 AI 建议条。
3
进度 = 任务自己的语义——产出型按产出数、积累型按打卡，时间只是辅助。计时器只用于"用户主动挂机"场景，绝不强制。
4
回来确认是闭环入口——站外任务完成后回来"勾选/打卡/完成"，系统自动算时长；忘了回来有兜底。

1. 共性结构（所有卡片通用，自上而下 5 区）

A 动机行「为四轴飞行器打好电路基础」· 紫色系 · 新字段 purpose（AI 推断/父级继承/可改）
B 行动区任务标题（17-18px 粗）+ 主按钮（大、品牌色/类型色）· 跳过/暂停为次级
C 执行工具按类型切换：时间块 / 子项清单（高亮下一个）/ 打卡面板 / 统计
D 回来确认区补记时长弹窗 / 打卡内容输入 / 勾选动作——"回来报到"的交互都在这层
E 元信息行归属 · 预计/已用时间 · 备注（＋备注）——全部小字角标，不抢视觉
区元素状态/文案规格数据
A 动机行purpose 文本≤50 字；无 purpose 时显示类型提示（"清单型 · 做产品/项目"）；紫色底浅字新增 Task.purpose
B 行动区标题 + 主按钮主按钮文案按状态：未出发=出发 / 出发中=进行中… / 完成态=已完成✓；固定时间型主按钮=完成已有
C 执行工具类型专属见 §3 五卡分案已有
D 回来确认补记弹窗/打卡内容出发后回来：弹"刚才做了多久？[30分][1小时][自定义]"（默认=现在−出发）；打卡型：内容输入框Task.departureAt / TimeLog.detail
E 元信息行归属/时间/备注9-10px 灰字一行或两行小字；备注入口保留（＋备注）已有
暂停按钮恢复（全部卡通用）：出发中状态下显示「暂停」，点击弹暂停原因（太难/注意力下降/临时有事/估时错误/其他）→ 数据走 UserObservation + Rule9（已有链路）。
✅ 2026-08-03 视觉定稿补充： ① 执行清单/动作清单颜色 = 对齐真实项目 v2-memo token：底 #fff9e6 / 左边条 #f5a623 / 标题字 #8b6914 / 勾选框 #d4a853（副本已按此渲染，落地零转换） ② 黄框内必须有小标题（memo 纸栏目感）：清单型=「执行清单」、学习型=「知识点」、健身=「今日动作」，标题下虚线分隔 ③ 卡片宽度策略：单栏最小宽度 420px（可用空间够时）；视口 ≥860px 自动切两栏；内容少的卡（固定时间型/学习型）可收窄至 360px——宽度匹配内容密度 ④ 固定时间型状态标签统一为「到点自动完成」（不用「自动计时」）

2. 卡片状态机（4 态）

状态触发UI 表现
未出发任务成为 currentTask动机行 + 标题 + 「出发」大按钮；C 区显示工具但可操作区灰化提示
出发中点「出发」→ 记 departureAt主按钮变「进行中…」；暂停按钮出现；计时型可挂机计时（手动）
回来确认回来点完成/打卡/勾选弹补记时长（默认=现在−出发，可改）；积累型弹内容输入（可选）
已完成 / 已打卡确认后按钮变「已完成✓」置灰；卡片自动滑到下一任务
忘记回来兜底：任务出发后一直未确认 → 下次打开 Today 时提示「该任务已过去 X 小时：① 完成了忘了记（补记）② 没做完，继续」。固定时间型到点（scheduledEnd 过）未确认 → 自动完成（TimeLog detail='auto'）。

3. 五卡分案（每种卡的分区规格）

3.1 固定时间型（上课/开会）低频 · 简化设计

A动机行（可选，如"专业必修课"）
B标题「数字电路」+ 主按钮「完成」（提前结束才点）
C时间块：09:00 - 10:30（大字号）· 教室/地点（如有）· 无计时器
E归属 · 预计时长
元素规格
主视觉时间块（开始-结束时间），不显示计时圆环；无出发按钮
自动完成scheduledEnd 过了 → 自动标记完成（惰性结算，打开页面时补算），TimeLog 记计划时长 detail='auto'
手动完成提前结束（早下课）点「完成」

3.2 清单型 / 学习型（产出类）核心卡

A「为四轴飞行器打好电路基础」
B「画原理图」+ 主按钮「出发」（出发中→「进行中…」）
C执行清单：第一个未完成子项高亮（左边条+底色），其余灰字 · 进度 1/3 + 总耗时（系统累计）
D回来点「该项完成」→ 该项勾掉 → 自动高亮下一项 · 弹补记时长
E归属 · 预计/已用 · ＋备注
交互规格
子项级出发循环点子项（或系统自动高亮第一个未完成项）→ 点「出发」→ 回来点「该项完成」→ 记录该项耗时（出发→完成）→ 自动跳下一项。总耗时=各项累计
高亮"下一个子项"第一个未完成子项：左侧 4px 品牌色条 + 浅色底 + 文字加深；设置里可开关（默认开）
学习型清单=知识点/节次（"3.2 逆矩阵"），同一套交互；无子任务时显示「建议下一步」（executionAdvice）或「＋拆成小节」入口，禁止空壳
进度条产出进度（完成子项数），时间只作为小字"总耗时 X 分钟"

3.3 积累型 · 每日（背单词）事后反馈模式

A「为考研词汇量冲刺」
B「背单词」+ 主按钮「出发」（出发中→「进行中…」）
C连续天数（当前/最长/本周）三格统计 + 小日历（保留现有设计）· 无预设清单
D回来点「打卡」→ 弹「今天背了哪些词？」输入框（可选，填了存 TimeLog.detail）→ 打卡完成
EAI 提醒（连续 X 天…）· hint
元素规格
打卡流程出发 → 背 → 回来打卡 + 可选输入今日内容（事后反馈：背完才知道背了啥）
内容输入打卡弹窗内：输入框"今天背了哪些词（可空）"→ TimeLog.detail；Review 可回顾"这周背了：xxx"
清单不强制 children；有则显示，无则简化（区别于健身）

3.4 积累型 · 频次（健身）事前规划模式

A「保持身体状态，支撑高强度学习」
B「力量训练」+ 主按钮「出发」
C今日动作清单（提前设好：引体向上 4×10 / 划船 4×12…）+ 周目标 1/3 + 周视图（保留）
D回来勾选今日动作 → 打卡（勾选内容存 TimeLog.detail）
EAI 提醒（"建议周五练第 2 次"）· hint
元素规格
动作清单提前编辑（Inbox 确认表单/档案面板 children）：今天的训练动作；卡片上提醒"今天练：3 个动作"
打卡流程出发 → 练 → 回来勾选动作（默认全勾，可改）→ 打卡
统计周目标进度 + 本周次数 + 累计时长（保留现有）

3.5 两栏版适配（视口 ≥ 860px 时）

沿用现有两栏骨架：左栏（灰底 flex:0.7-0.8）= 数据区（动机行放左栏顶部 or 右栏标题上方？建议：动机行横跨两栏顶部，保持"第一视觉"）；右栏（白底）= 执行区（标题+按钮+工具+确认）。具体分割由 UI 设计师按 3.1-3.4 内容量裁定。

4. 新增组件规格

组件规格
动机行（purpose）全宽细条，紫色浅底（var(--purple-bg)）+ 紫字，≤50 字，可带小图标（如 🎯 由设计师定）；无 purpose 时退化为类型 hint
补记时长弹窗回来确认时弹：标题"刚才做了多久？" + 选项 [30 分钟][1 小时][自定义输入]（默认=现在−出发时刻，标注"从 X:XX 出发"）
暂停原因弹窗点暂停弹：单选（太难/注意力下降/临时有事/估时错误/其他）+ 确定；数据走 UserObservation
忘记确认提示条Today 顶部提示："「画原理图」出发后未确认，已过去 7 小时：① 完成了忘了记 ② 没做完，继续"
打卡内容输入打卡弹窗内文本输入（背单词："今天背了哪些词？"）/ 动作勾选列表（健身）；均可空

5. 数据字段（后端契约，UI 先行用 mock）

字段类型说明状态
Task.purposeString? ≤50动机行文案；AI 推断+父级继承+Inbox/档案可改新增
Task.departureAtDateTime?出发时刻；补记时长默认值来源；忘记确认兜底新增
TimeLog.detailString?打卡内容（背了哪些词/勾选动作）/ auto 标记新增
暂停原因UserObservationtype=pause + detail.reason（已有链路，前端恢复按钮）已有
固定时间自动完成—惰性结算（打开页面补算过期 scheduledEnd）新增逻辑
实施顺序：① 前端 UI（mock 数据，本文档为视觉稿依据）→ ② 后端字段+逻辑 → ③ 对接。UI 设计师可先用 mock 的 purpose/departureAt/detail 渲染全部状态。
